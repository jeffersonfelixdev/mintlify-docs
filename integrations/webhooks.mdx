## Descrição

Um webhook é uma requisição HTTP que a ZapperHub envia à sua aplicação quando um
evento acontece na instância. O webhook substitui a consulta periódica
(*polling*): a aplicação recebe o dado no momento do evento.

## Eventos disponíveis

| Evento | Quando é publicado |
| --- | --- |
| `messages.upsert` | A instância recebeu ou enviou uma mensagem |
| `contacts.preference` | O contato pediu para parar, ou voltou a aceitar, mensagens de marketing. Ou o integrador marcou isso pela API. Só em conexão oficial. Assinatura opt-in |
| `contacts.identity` | O vínculo entre telefone, BSUID e username de um contato mudou. Só em conexão oficial. Assinatura opt-in |
| `messages.update` | O contato editou ou apagou uma mensagem recebida. Só em conexão oficial, em número em coexistência com o WhatsApp Business. Assinatura opt-in |
| `messages.status` | O estado de uma mensagem enviada mudou. Em conexão oficial: enviada, entregue, lida ou falhou. Em conexão não oficial: entregue ou lida |
| `messages.error` | O envio de uma mensagem falhou em definitivo |
| `connection.update` | A conexão da instância abriu ou fechou |
| `group-participants.update` | Participantes entraram, saíram, foram promovidos ou rebaixados em um grupo. Só em conexão não oficial |
| `calls.update` | Uma chamada de voz ou vídeo foi recebida, atendida ou encerrada. Em conexão oficial e não oficial |
| `comments.upsert` | A conta recebeu um comentário em um post. Só em instância do Instagram |
| `token.expired` | O token do Instagram expirou ou foi revogado. Exige nova autorização |
| `token.refresh.failed` | Uma tentativa de renovar o token do Instagram falhou |
| `webhook.test` | Requisição de teste, enviada uma única vez no cadastro do webhook |

Cada webhook recebe só os eventos que assinou. A assinatura é a lista
`subscriptions` informada no cadastro.

## Cadastrar um webhook

### Pelo painel

Abra **Instâncias**, selecione a instância, abra **Webhook** e clique em **Novo
Webhook**. O procedimento, as validações e o limite de webhooks por instância
estão em [Webhooks no painel](/painel/webhooks).

### Pela API

Envie `POST /{instanceId}/webhooks` com um nome, a URL e os eventos:

```json
{
  "name": "Integração CRM",
  "url": "https://exemplo.com/webhooks/zapperhub",
  "subscriptions": ["messages.upsert", "messages.error", "connection.update"]
}
```

A URL deve usar HTTPS. Antes de criar o cadastro, a ZapperHub envia uma
requisição `POST` de teste (`webhook.test`) à URL. Se a URL não responder com
sucesso, a ZapperHub não cria o webhook.

As rotas de listagem, atualização e exclusão estão na seção
[Webhooks](/api-reference/webhook/listar-webhooks) da API Reference.

## Autenticidade das requisições

Toda entrega leva o cabeçalho `x-webhook-signature`. O valor é o HMAC-SHA256 do
corpo da requisição, exatamente como recebido, com a chave de API da instância
como segredo. As requisições levam o `User-Agent` `ZapperHub API`.

Para validar, recalcule a assinatura sobre o corpo bruto e compare:

```javascript
import { createHmac, timingSafeEqual } from 'node:crypto'

function isFromZapperHub(rawBody, signature, apiKey) {
  const expected = createHmac('sha256', apiKey).update(rawBody, 'utf8').digest('hex')
  return timingSafeEqual(Buffer.from(expected), Buffer.from(signature))
}
```

<Warning>
**Valide a assinatura.** A assinatura é a única forma de garantir que a
requisição veio da ZapperHub. A validação é responsabilidade da sua aplicação.
Proteja a aplicação também com outras regras, como limite de taxa e TLS. Não
envie a chave de API a terceiros.
</Warning>

<Note>
A requisição de teste do cadastro (`webhook.test`) é a única sem assinatura. Ela
ocorre antes de o webhook existir.
</Note>

## Entrega

A ZapperHub entrega cada evento por uma fila própria, com 5 tentativas e
intervalo crescente, a partir de 10 segundos. Cada tentativa tem 7 segundos de
timeout. Uma URL que demora mais do que isso conta como falha.

Responda com um status de sucesso o mais rápido possível. Processe o conteúdo
depois da resposta.

A ZapperHub registra cada tentativa em um recibo de entrega, com o horário e o
erro, quando há. Consulte os recibos por `GET /{instanceId}/webhook-receipts` ou
em **Ver recibos de entrega**, no [Log de mensagens](/painel/log-de-mensagens).

<Note>
A ZapperHub guarda os arquivos recebidos pelos webhooks por 7 dias. Veja
[Armazenamento de arquivos](/definitions/storage).
</Note>

## Eventos da própria sessão

O webhook também traz as mensagens enviadas pela própria conta conectada. O
motivo é a fila: no momento do envio, a API devolve só o `jobId`, não o id da
mensagem.

Uma mensagem com o campo `jobId` foi enviada pela ZapperHub. Uma mensagem
enviada por outro dispositivo não tem esse campo.

## Estrutura do payload

Os eventos de mensagem compartilham a mesma estrutura. O conteúdo do objeto
`message` muda conforme o tipo.

| Campo | Conteúdo |
| --- | --- |
| `type` | O evento, um dos listados acima |
| `instanceId` | Id da instância que gerou o evento |
| `chatId` | Id da conversa |
| `key.remoteJid` | JID da conversa: o contato ou o grupo |
| `key.fromMe` | `true` quando a mensagem partiu da conta conectada |
| `key.id` | Id da mensagem no WhatsApp |
| `key.senderPn` / `key.senderLid` | Número e LID de quem enviou, em conversa individual |
| `key.participantPn` / `key.participantLid` | Número e LID de quem enviou, em grupo |
| `messageTimestamp` | Momento da mensagem, em segundos |
| `pushName` | Nome de exibição de quem enviou |
| `message` | O conteúdo, no formato do tipo da mensagem |
| `mediaUrl` | URL do arquivo processado, nas mensagens de mídia |
| `jobId` | Id do job na fila. Presente nas mensagens enviadas pela API |
| `trackId` / `trackSource` | Os valores informados no envio. Em mensagens recebidas, `trackSource` é `whatsapp` |

Em conexão oficial (Cloud API), os eventos também trazem o corpo original da
Meta, nos campos `object` e `entry`.

## Exemplos de payload

### Teste do webhook

Tipo: `webhook.test`

A ZapperHub envia este evento uma única vez, no cadastro, para verificar se a URL
aceita requisições `POST`.

```json
{
  "type": "webhook.test",
  "instanceId": "inst_01hxyz1234567890",
  "message": "If you see this message, your webhook is working correctly."
}
```

### Atualização da conexão

Tipo: `connection.update`

Publicado quando a instância conecta (`open`) ou desconecta (`close`). O campo
`reason` aparece nas desconexões com causa conhecida, como uma conta removida na
Meta ou um token do Instagram expirado.

```json
{
  "type": "connection.update",
  "instanceId": "inst_01hxyz1234567890",
  "connection": "close",
  "reason": "token_expired"
}
```

**Reação** (Cloud API e Instagram)

Quando o contato reage a uma mensagem, ou o número reage pelo aparelho em modo
de coexistência, chega um `messages.upsert` com `reactionMessage`. O `key.id` do
evento é o da própria reação. A mensagem reagida está em
`reactionMessage.key.id`.

No Instagram, o evento chega com `trackSource: "instagram"`. O `key.id` é
composto (`ig-reaction:<mid>:<remetente>:<timestamp>`). A retirada vem com
`removed: true`. O restante do formato é o mesmo.

```json
{
  "type": "messages.upsert",
  "instanceId": "inst_01hxyz1234567890",
  "chatId": "5512912345678@s.whatsapp.net",
  "key": {
    "remoteJid": "5512912345678@s.whatsapp.net",
    "fromMe": false,
    "id": "wamid.HBgLNTUxMjkxMjM0NTY3OBUCABIYFjNFQjA",
    "senderPn": "5512912345678@s.whatsapp.net"
  },
  "messageTimestamp": 1744398716,
  "pushName": "John Doe",
  "broadcast": false,
  "message": {
    "reactionMessage": {
      "key": {
        "remoteJid": "5512912345678@s.whatsapp.net",
        "fromMe": true,
        "id": "3AB16AB78CD9012E89A0"
      },
      "text": "👍",
      "senderTimestampMs": 1744398716000
    }
  },
  "removed": false,
  "trackSource": "whatsapp"
}
```

- `reactionMessage.text` é o emoji. Quando o contato retira a reação, `text` vem vazio (`""`), e `removed` vem `true`.
- `reactionMessage.key.fromMe` indica de quem é a mensagem reagida: `true` quando
  o contato reagiu a uma mensagem da empresa, `false` quando o número reagiu, pelo
  aparelho, a uma mensagem do contato.
- Uma segunda reação à mesma mensagem é um evento novo, com outro `key.id`.
- Para reagir, use [`POST /{instanceId}/messages/react`](/functions/sending-messages#reagir-a-uma-mensagem).

### Outros tipos de mensagem recebidos

Tipo: `messages.upsert`

Além de texto, mídia, localização, contato e resposta de botão ou lista, a
conexão oficial (Cloud API) entrega os tipos abaixo. Todos chegam no mesmo
envelope das outras mensagens (`chatId`, `key`, `messageTimestamp`, `pushName`) e
aparecem em `GET /{instanceId}/messages` com o tipo correspondente. Nenhuma
mensagem é descartada. Um tipo que a ZapperHub não conhece chega como
`unknownMessage`.

| Conteúdo em `message` | Quando chega | Campos |
| --- | --- | --- |
| `flowResponseMessage` | O contato responde a um Flow | `name`, `body`, `responseJson` e `contextInfo.stanzaId` (o Flow respondido) |
| `callPermissionReplyMessage` | O contato responde ao pedido de permissão de ligação | `response` (`accept` ou `reject`), `expiresAt`, `permanent`, `source` e `contextInfo.stanzaId` |
| `systemMessage` | A Meta avisa de uma mudança na conversa, como a troca de número do contato | `type` (por exemplo `user_changed_number` ou `user_changed_user_id`) e `body` |
| `orderMessage` | O contato envia um pedido do catálogo | `catalogId`, `text` e `items[]` com `productRetailerId`, `quantity`, `itemPrice` e `currency` |
| `unsupportedMessage` | A Meta não repassa o tipo (enquete, edição fora da coexistência etc.) | `type` (o tipo informado pela Meta, como `edit`) e `error` (`code`, `title`, `details`) |
| `unknownMessage` | Qualquer tipo sem tratamento próprio | `type` (o tipo bruto da Meta) e `raw` (a mensagem original) |

```json
{
  "type": "messages.upsert",
  "instanceId": "inst_01hxyz1234567890",
  "chatId": "5512912345678@s.whatsapp.net",
  "key": {
    "remoteJid": "5512912345678@s.whatsapp.net",
    "fromMe": false,
    "id": "wamid.HBgNNTUxMjkxMjM0NTY3OBUC",
    "senderPn": "5512912345678@s.whatsapp.net"
  },
  "messageTimestamp": 1785312060,
  "pushName": "John Doe",
  "broadcast": false,
  "message": {
    "flowResponseMessage": {
      "name": "flow",
      "body": "Enviado",
      "responseJson": { "flow_token": "tk_123", "nome": "Maria" },
      "contextInfo": {
        "stanzaId": "wamid.FLOW",
        "participant": "5511900000000@s.whatsapp.net"
      }
    }
  },
  "trackSource": "whatsapp"
}
```

- `flowResponseMessage.responseJson` é o objeto que o Flow devolveu. Se a Meta
  entregar um texto que não é JSON válido, ele vai como texto.
- `callPermissionReplyMessage.expiresAt` é a validade da permissão, em ISO 8601.
  Só vem em permissão temporária. `permanent` é `true` quando o contato aceitou
  de forma permanente.
- `systemMessage` informa o fato. A ZapperHub também atualiza o vínculo do
  contato em troca de número ou de BSUID. Veja
  [Identidade do contato](#identidade-do-contato-telefone-bsuid-e-username).
- Uma mensagem `unsupported` continua a gerar também o `messages.error` com o
  código 131051.
- `unknownMessage.raw` traz a mensagem original da Meta. Assim, você trata o tipo
  novo sem esperar uma atualização da ZapperHub.

### Identidade do contato: telefone, BSUID e username

A Meta identifica os contatos por um BSUID (`BR.13491208655302741918`). Quando o
contato adota um username, a Meta pode omitir o telefone. A ZapperHub guarda o
vínculo entre os três, por empresa (WABA) e por dono. Todas as suas instâncias na
mesma WABA compartilham o vínculo. Outro dono nunca vê o vínculo, mesmo com a
mesma WABA.

O `key.remoteJid` (e o `chatId`) de uma mensagem segue esta ordem:

1. O telefone, quando a Meta o informa no evento.
2. O telefone já conhecido para aquele BSUID.
3. O próprio BSUID, quando o telefone é desconhecido.

`key.bsuid` e `username` acompanham a mensagem quando são conhecidos: nas
mensagens recebidas, nos ecos de mensagens enviadas pelo aparelho e nos
[status de entrega](#estado-de-entrega-da-mensagem).

Tipo: `contacts.identity`

Quando o vínculo muda, a ZapperHub publica este evento em cada instância do mesmo
dono na WABA. Use o evento para juntar duas conversas do mesmo contato.

```json
{
  "type": "contacts.identity",
  "instanceId": "inst_01hxyz1234567890",
  "reason": "phone_discovered",
  "previous": { "phone": null, "bsuid": "BR.13491208655302741918", "username": "fulano" },
  "current": { "phone": "5512912345678", "bsuid": "BR.13491208655302741918", "username": "fulano" },
  "chatId": {
    "previous": "BR.13491208655302741918",
    "current": "5512912345678@s.whatsapp.net"
  },
  "timestamp": 1760000000
}
```

| `reason` | O que aconteceu |
| --- | --- |
| `phone_discovered` | Um contato que só tinha BSUID teve o telefone revelado |
| `phone_changed` | O contato trocou de número |
| `bsuid_changed` | O contato mudou de BSUID |
| `link_removed` | O telefone passou a pertencer a outro BSUID e deixou este vínculo |

- Use `chatId.previous` e `chatId.current` para migrar o histórico da conversa antiga para a nova.
- Uma entrega repetida da Meta não republica o evento.
- A primeira vez que a ZapperHub vê um contato não gera evento. Só mudanças geram evento.
- A assinatura é opt-in. Inclua `contacts.identity` em `subscriptions`.

### Opt-out de marketing

Tipo: `contacts.preference`

Quando um contato pede para parar, ou volta a aceitar, mensagens de marketing,
pela Meta ou pela [API de contatos](/functions/contacts#opt-out-de-marketing), a
ZapperHub publica este evento em todas as instâncias do mesmo dono na mesma WABA.

```json
{
  "type": "contacts.preference",
  "instanceId": "inst_01hxyz1234567890",
  "contact": { "phone": "5512912345678", "bsuid": "BR.13491208655302741918" },
  "category": "marketing_messages",
  "status": "opted_out",
  "source": "meta",
  "timestamp": 1731705721
}
```

- `status` é `opted_out` (não recebe marketing) ou `opted_in` (voltou a aceitar).
- `source` é `meta` (o contato pediu) ou `manual` (o integrador marcou pela API).
- `contact.phone` e `contact.bsuid` trazem o que a ZapperHub conhece do contato. Qualquer um pode ser `null`.
- Entre a escolha da Meta e a manual, vale a mais recente.
- A mesma escolha repetida não gera um segundo evento.
- Com `opted_out`, a API recusa templates de marketing para o contato com `MARKETING_OPT_OUT`. Utilidade e autenticação seguem.
- A assinatura é opt-in. Inclua `contacts.preference` em `subscriptions`.

### Mensagem editada ou apagada

Tipo: `messages.update`

Quando o contato edita ou apaga uma mensagem, ou o próprio número faz isso pelo
aparelho, a ZapperHub publica este evento. O evento aponta para a mensagem
original: `key.id` é o id dela, o mesmo recebido antes em `messages.upsert`. O id
do evento de edição ou remoção vem em `eventId`.

```json
{
  "type": "messages.update",
  "instanceId": "inst_01hxyz1234567890",
  "chatId": "5512912345678@s.whatsapp.net",
  "key": {
    "remoteJid": "5512912345678@s.whatsapp.net",
    "fromMe": false,
    "id": "wamid.HBgLNTUxMjkxMjM0NTY3OBUCABIYFjNFQjA"
  },
  "update": {
    "kind": "edited",
    "message": {
      "extendedTextMessage": { "text": "Texto corrigido" }
    }
  },
  "eventId": "wamid.HBgLNTUxMjkxMjM0NTY3OBUCABIYFjNGQzE",
  "timestamp": 1749854575
}
```

Na remoção, `update` vem só com o tipo:

```json
{ "update": { "kind": "deleted" } }
```

- `update.kind` é `edited` ou `deleted`.
- Na edição, `update.message` traz o texto novo (`extendedTextMessage`) ou a
  legenda nova (`imageMessage`, `videoMessage` ou `documentMessage`, com
  `caption`). A mídia não é reenviada. Se a Meta não informa o conteúdo novo,
  `update.message` é omitido.
- A assinatura é opt-in. Inclua `messages.update` em `subscriptions`. Quem assina
  só `messages.upsert` continua a receber o que recebia.
- A Meta só envia estes eventos para números em coexistência com o app do
  WhatsApp Business. A edição vale até 15 minutos depois do envio. A remoção vale
  até 2 dias.
- A mesma edição ou remoção entregue duas vezes pela Meta gera um único evento.

<Note>
A Meta entrega as edições como mensagem de tipo não suportado, não no formato
próprio de edição. Por isso, a edição chega como `messages.upsert` com
[`unsupportedMessage`](#outros-tipos-de-mensagem-recebidos) de `type` `edit`,
sem o texto novo, e não como `messages.update`. A remoção gera `messages.update`.
</Note>

### Escolha de opção em mensagem de lista

Tipo: `messages.upsert`

Publicado quando o contato seleciona uma opção da lista. O formato é o mesmo em
instância oficial (Cloud API) e não oficial:

- `message.listResponseMessage.selectedButtonId`: o `rowId` exato da opção escolhida, como definido no envio.
- `message.listResponseMessage.selectedDisplayText`: o texto exibido da opção.
- `message.listResponseMessage.contextInfo.stanzaId`: o id da mensagem de lista original.

```json
{
  "type": "messages.upsert",
  "instanceId": "inst_01hxyz1234567890",
  "chatId": "5512912345678@s.whatsapp.net",
  "key": {
    "remoteJid": "5512912345678@s.whatsapp.net",
    "fromMe": false,
    "id": "4D2AAEC025A74710866EF732A614AABA",
    "senderPn": "5512912345678@s.whatsapp.net"
  },
  "messageTimestamp": 1785312060,
  "pushName": "John Doe",
  "broadcast": false,
  "message": {
    "listResponseMessage": {
      "selectedButtonId": "cafe-01",
      "selectedDisplayText": "Café",
      "contextInfo": {
        "stanzaId": "3AB16AB78CD9012E89A0",
        "participant": "5512912345678@s.whatsapp.net"
      }
    }
  },
  "trackSource": "whatsapp"
}
```

<Note>
Em instâncias não oficiais, o bloco `listResponseMessage` traz também os campos
nativos do provedor (`title`, `description`, `listType`,
`singleSelectReply.selectedRowID`). A diferença é aditiva. Uma integração que lê
só `selectedButtonId` e `selectedDisplayText` funciona nos dois canais.
</Note>

A resposta a uma mensagem com botões chega da mesma forma, em
`message.buttonsResponseMessage`.

### Estado de entrega da mensagem

Tipo: `messages.status`

Publicado a cada mudança de estado de uma mensagem enviada, em instâncias
oficiais (Cloud API) e não oficiais (`device`). Na Cloud API, `status` segue os
valores da Meta: `sent`, `delivered`, `read` e `failed`. `error` só aparece nas
falhas.

```json
{
  "type": "messages.status",
  "instanceId": "inst_01hxyz1234567890",
  "messageId": "wamid.HBgNNTUxMjkxMjM0NTY3OBUCABEYEjc0NjcyOTk2MEE1MEJDNTY2AA==",
  "recipientId": "5512912345678",
  "status": "delivered",
  "timestamp": 1785312030
}
```

#### Em conexão não oficial (`device`)

O evento chega com `status` `delivered` (dois checks) ou `read` (dois checks
azuis), uma vez por mensagem. Quando o WhatsApp agrupa vários recibos, cada
mensagem do lote gera o seu evento. O `messageId` é o mesmo `key.id` recebido no
`messages.upsert` do envio.

```json
{
  "type": "messages.status",
  "instanceId": "inst_01hxyz1234567890",
  "messageId": "3AB16AB78CD9012E89A0",
  "recipientId": "5512912345678",
  "recipientPn": "5512912345678",
  "chatId": "5512912345678@s.whatsapp.net",
  "status": "read",
  "timestamp": 1785312030
}
```

- `chatId` é a conversa. Quando a conversa é identificada por LID, o evento traz
  `recipientLid` com o LID e, se a ZapperHub conhece o vínculo, `recipientPn` com
  o telefone. Sem o vínculo, `recipientId` carrega o LID.
- Não há `sent` nem `failed` em conexão não oficial. A confirmação de envio é a
  resposta da API. A falha definitiva chega em `messages.error`.
- Recibos de grupo não são entregues.
- Se o contato desativou a confirmação de leitura, o evento `read` não chega. Só o `delivered` chega.
- Para informar ao WhatsApp que você leu uma mensagem, use
  [Marcar como lida](/functions/sending-messages#marcar-como-lida).

#### Em conexão oficial (Cloud API)

Quando a ZapperHub conhece o BSUID ou o username do destinatário, o evento traz
também `bsuid` e `username`. Se o destinatário não tem telefone visível,
`recipientId` carrega o BSUID.

### Falha no envio de mensagens

Tipo: `messages.error`

O `200` da API confirma o enfileiramento, não a entrega. Quando as 5 tentativas
de envio se esgotam, a ZapperHub publica este evento. Nenhuma mensagem chegou ao
destinatário. Uma falha intermediária seguida de sucesso não gera o evento.

O evento vale para todos os tipos de mensagem enviados pela API.

```json
{
  "type": "messages.error",
  "instanceId": "inst_01hxyz1234567890",
  "jobId": "42",
  "key": {
    "id": "job_42",
    "fromMe": true,
    "remoteJid": "5512912345678@s.whatsapp.net"
  },
  "error": {
    "code": 131000,
    "title": "Something went wrong",
    "message": "Message failed to send because of an unknown error.",
    "error_data": {
      "details": "connect ETIMEDOUT 10.0.0.1:443"
    },
    "href": "https://developers.facebook.com/docs/whatsapp/cloud-api/support/error-codes/"
  },
  "timestamp": 1753758000,
  "trackId": "pedido-8823",
  "trackSource": "crm"
}
```

- O bloco `error` segue o formato de erro da Cloud API. Uma integração escrita
  para aquele formato lê este evento sem tratamento novo.
- `error.code` repassa o código original da Meta quando a falha veio da Cloud API
  (por exemplo, `131047` para janela de 24 horas expirada, ou `131026` para
  destinatário inalcançável). O código `131000` é usado quando não há código de
  provedor: instâncias não oficiais, timeout e falhas de rede.
- `error.error_data.details` traz o erro real do envio. `error.message` é a descrição estável do código.
- `error.localizedMessage` traz a explicação em português para os códigos da Meta
  que a ZapperHub conhece. Exemplo, `131047`: "Passaram mais de 24 horas desde a
  última mensagem do contato. Envie um template de mensagem." O campo só aparece
  quando há tradução.
- `key.id` é derivado do job (`job_<jobId>`), não do provedor. O envio nunca
  produziu um id de mensagem. Esse formato distingue uma falha da fila de um erro
  da Meta.
- `trackId` e `trackSource` são os mesmos informados no envio.

### Mudança de participantes em grupo

Tipo: `group-participants.update`

Publicado em instâncias não oficiais quando alguém entra, sai, é promovido a
administrador ou rebaixado. Os campos `join`, `leave`, `promote` e `demote`
trazem os participantes afetados. Só o campo correspondente ao que aconteceu vem
preenchido. Os outros são omitidos.

```json
{
  "type": "group-participants.update",
  "groupId": "120363012345678901@g.us",
  "join": ["5512912345678@s.whatsapp.net"],
  "timestamp": "2026-07-29T12:00:00Z"
}
```

#### Valores de `event` por origem

| `event` | Conexão oficial (Cloud API) | Conexão não oficial (`device`) |
| ------- | --------------------------- | ---------------------------- |
| `connect` | Chamada do usuário chegando ao número. Sem `status` | Chamada chegando ao número. Sem `status` |
| `status` | Progresso da chamada: `RINGING`, `ACCEPTED` ou `REJECTED` | Chamada atendida: `ACCEPTED` |
| `terminate` | Encerramento: `COMPLETED` ou `FAILED` | Encerramento: `REJECTED`, `MISSED`, `ACCEPTED`, `COMPLETED`, `FAILED`, ou omitido |
| `error` | Falha reportada pela Meta | Não ocorre |

`MISSED` (chamada que tocou até expirar) só existe na conexão não oficial. A
conexão oficial não publica esse desfecho.

Em conexão não oficial, `status` ausente em um `terminate` significa que o
motivo não é previsto pela plataforma. Use `reason`, que vem sempre.

#### Diferenças entre as duas origens

| | Conexão oficial (Cloud API) | Conexão não oficial (`device`) |
| --- | --- | --- |
| Campos exclusivos | `startTime`, `endTime`, `duration`, `bizOpaqueCallbackData`, `username` | `reason`, `groupId`, `key.senderLid` / `key.participantLid` |
| `key.addressingMode` | Sempre `pn` | `pn` ou `lid`, conforme o contato |
| Chamada de grupo | Não se aplica | `groupId` e `key.participantPn` |
| Ocorrência bruta | Nos campos `object` e `entry` | Em `rawEvent` |

Um campo sem valor na origem é omitido. A ZapperHub nunca envia `null` ou string
vazia nesse caso.

<Note>
**A assinatura de `calls.update` é opt-in.** Inclua a string em `subscriptions`.
Nenhuma assinatura existente muda automaticamente. Assine pelo seletor de
eventos do painel, ou pela API com `PUT /{instanceId}/webhooks/{webhookId}`.

Chamada não é mensagem. O evento não é encaminhado ao Chatwoot e não é gravado
no histórico de conversas.
</Note>

<Warning>
**Conexão oficial: a assinatura habilita as chamadas no número.** A Meta só emite
eventos de chamada, e só mostra o botão de ligação ao usuário, em número com o
recurso de chamadas habilitado. Um número Cloud API nasce com o recurso
desligado.

Por isso, ao assinar `calls.update`, a plataforma habilita o recurso no número
antes de salvar o webhook. Você não precisa fazer nada na Meta. Se o recurso já
está habilitado, nada muda: horário de atendimento, visibilidade do botão e SIP
permanecem.

Quando a habilitação não é possível, o webhook não é salvo. A resposta informa o caso:

| Resposta | `code` | O que fazer |
|---|---|---|
| `422` | `CALLING_API_UNAVAILABLE` | O número não se qualifica para a Calling API. Salve de novo sem `calls.update`. Repetir o mesmo pedido falha de novo |
| `503` | `PROVIDER_UNAVAILABLE` | A Meta não respondeu. Repita o mesmo pedido em instantes |

A recusa vale para o pedido inteiro. Nome, URL e as outras assinaturas também não
são gravados.

Os pré-requisitos da Calling API são da Meta: número Cloud API nativo
(coexistência não se qualifica), limite diário de pelo menos 2.000 destinatários
únicos e campo `calls` assinado na configuração do aplicativo.

Em conexão não oficial, nada disso se aplica. As chamadas chegam sem
configuração, e a assinatura não passa por essa verificação.
</Warning>

<Warning>
Em conexão não oficial, chamadas recebidas enquanto a instância estava
desconectada não são recuperadas. O WhatsApp não as reentrega quando a sessão
volta. O evento não existe para a instância.
</Warning>

### Gravação disponível

Tipo: `calls.update`, com `event: "recording"`

Publicado quando a gravação de uma chamada fica pronta, em conexão não oficial,
só para chamadas com gravação solicitada. É um evento separado do encerramento.
O encerramento sai assim que a chamada termina, sem esperar o processamento da
gravação. Correlacione os dois pelo `callId`.

```json
{
  "type": "calls.update",
  "instanceId": "inst_01hxyz1234567890",
  "chatId": "5511999999999@s.whatsapp.net",
  "key": {
    "remoteJid": "5511999999999@s.whatsapp.net",
    "fromMe": false,
    "id": "3EB0C767D26B8CE6A1B4",
    "addressingMode": "pn",
    "senderPn": "5511999999999@s.whatsapp.net"
  },
  "callId": "3EB0C767D26B8CE6A1B4",
  "event": "recording",
  "direction": "USER_INITIATED",
  "timestamp": 1787072580,
  "trackSource": "whatsapp",
  "recording": {
    "status": "AVAILABLE",
    "url": "https://storage.zapperhub.com/...&X-Amz-Expires=3600",
    "expiresAt": "2026-09-04T19:23:47.000Z",
    "durationSeconds": 216,
    "truncated": false
  }
}
```

O arquivo contém os dois lados da conversa. O endereço vem assinado. O download
não exige autenticação nem destino próprio.

| Campo | Descrição |
| --- | --- |
| `recording.status` | `AVAILABLE` ou `UNAVAILABLE` |
| `recording.url` | Endereço de download, válido por 1 hora |
| `recording.expiresAt` | Quando este endereço expira |
| `recording.durationSeconds` | Duração do áudio gravado |
| `recording.truncated` | `true` quando a gravação foi cortada no limite de 1 hora |

Um endereço expirado não é problema. Consulte
`GET /{instanceId}/calls/{callId}` para obter um novo, enquanto a gravação
existir.

Quando a gravação fica indisponível em definitivo, o mesmo evento traz o motivo.
O evento de encerramento, já entregue, não é reenviado:

```json
{
  "event": "recording",
  "callId": "3EB0C767D26B8CE6A1B4",
  "recording": { "status": "UNAVAILABLE", "reason": "STORAGE_FAILED" }
}
```

<Warning>
**A gravação expira em 7 dias.** Depois de 7 dias do encerramento, a plataforma
descarta o arquivo em definitivo. O registro da chamada continua consultável por
90 dias e informa que a gravação não existe mais. Baixe e guarde o arquivo no seu
lado se precisar dele por mais tempo.
</Warning>

Veja [Chamadas](/functions/calls) para originar, atender, gravar e encerrar
chamadas por API.

### Comentário recebido no Instagram

Tipo: `comments.upsert`

Publicado em instâncias do Instagram quando a conta recebe um comentário em um
post. A estrutura é a mesma de `messages.upsert`, mais o bloco `comment`.

```json
{
  "type": "comments.upsert",
  "key": {
    "id": "17984523698451234",
    "fromMe": false,
    "remoteJid": "17841400000000000",
    "senderId": "17841400000000000",
    "recipientId": "17841411111111111"
  },
  "messageTimestamp": 1785312000,
  "pushName": "john.doe",
  "broadcast": false,
  "message": {
    "extendedTextMessage": {
      "text": "Vocês entregam em São Paulo?"
    }
  },
  "comment": {
    "id": "17984523698451234",
    "text": "Vocês entregam em São Paulo?",
    "postId": "17895695668004550",
    "parentCommentId": null,
    "from": {
      "id": "17841400000000000",
      "username": "john.doe"
    },
    "timestamp": 1785312000
  },
  "trackSource": "instagram"
}
```

<Warning>
O comentário é público. Qualquer visitante do perfil o vê. O comentário não é
encaminhado ao Chatwoot e não é deduplicado. A Meta pode reentregar a mesma
notificação. Use `comment.id` como chave de idempotência e ignore entregas
repetidas do mesmo id.
</Warning>

Para responder em privado ao autor do comentário, use `commentId` em
`POST /{instanceId}/messages/text`.

### Token do Instagram expirado

Tipo: `token.expired`

Publicado quando o token de acesso do Instagram expirou ou foi revogado. É um
evento terminal. A instância é desconectada e exige nova autorização. Um
`connection.update` com `connection: "close"` acompanha o evento.

```json
{
  "type": "token.expired",
  "instanceId": "inst_01hxyz1234567890",
  "reason": "token_expired",
  "expiredAt": "2026-07-29T03:00:00.000Z",
  "requiresReauth": true
}
```

O campo `reason` é `token_expired` ou `token_revoked`.

### Falha ao renovar o token do Instagram

Tipo: `token.refresh.failed`

Publicado a cada tentativa de renovação que falha por causa temporária, como uma
instabilidade da Meta. A renovação continua a ser tentada. `failureCount` acumula
as falhas. Use o valor para escalar o alerta interno antes que a falha se torne
terminal.

```json
{
  "type": "token.refresh.failed",
  "instanceId": "inst_01hxyz1234567890",
  "origin": "automatic",
  "failureCount": 3,
  "reason": "temporary",
  "errorCode": 190,
  "expiresAt": "2026-08-15T03:00:00.000Z"
}
```

`origin` indica se a tentativa partiu da rotina automática (`automatic`) ou da
rota de renovação manual (`manual`).

<Note>
Sem a assinatura de `token.refresh.failed` e `token.expired`, você só percebe o
problema quando ele é terminal, pelo `connection.update`. Você não recebe aviso
durante a janela de retentativa.
</Note>
