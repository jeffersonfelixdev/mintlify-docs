## Descrição

As [chamadas por API](/functions/calls) fazem avisos automatizados: a plataforma
liga e reproduz um arquivo. O softphone permite a conversa.

Com o softphone, o atendente clica em um botão no seu sistema. A ligação sai pelo
número de WhatsApp da instância. O atendente fala pelo microfone do computador e
ouve o contato pelo fone, em tempo real.

Você inclui uma biblioteca na sua tela. A plataforma cuida de microfone,
reprodução, transporte e reconexão.

<Warning>
**Disponível só em conexão não oficial.** O softphone vale só para instâncias de
conexão não oficial (`device`). Em conexão oficial (Cloud API), qualquer operação
responde `422` com `code: UNSUPPORTED_FOR_INSTANCE_TYPE`.
</Warning>

## Limites

| Limite | Valor |
| --- | --- |
| Chamadas simultâneas | Uma por instância, inclusive a que ainda toca |
| Atendentes conectados | Vários por instância, na mesma linha |
| Contexto do navegador | HTTPS obrigatório. O navegador exige HTTPS para usar o microfone |
| Vídeo | Não disponível |
| Chamada em grupo | Não disponível |
| Transferência de chamada | Não disponível |
| Espera | Não disponível |
| Teclado de tons (DTMF) | Não disponível |
| Duração da conversa | Sem limite |
| Gravação | Mesmas regras de [Chamadas](/functions/calls): 30 por dia, 1 hora, 7 dias de retenção |

## Como funciona

<Steps>
  <Step title="O seu backend emite a credencial do atendente">
    Uma rota sua troca a `x-api-key` da instância por uma credencial de curta
    duração, vinculada a um atendente.
  </Step>
  <Step title="A biblioteca abre a sessão">
    O componente no navegador usa a credencial para abrir a sessão de voz com a instância.
  </Step>
  <Step title="O atendente conversa">
    Ligar, atender, silenciar e encerrar acontecem pelo componente. Você desenha
    os botões. A biblioteca entrega o estado e os comandos.
  </Step>
</Steps>

<Warning>
**Nunca envie a `x-api-key` ao navegador.** Quem tem a chave pode discar em nome
da empresa e ler conversas de outras instâncias. Uma extensão maliciosa na
máquina do atendente também pode lê-la. A credencial de curta duração existe
para isso.
</Warning>

## Pré-requisitos

<Warning>
**Cadastre a origem do seu sistema.** A credencial do atendente só vale para as
páginas servidas em uma origem específica, cadastrada na instância. Sem o
cadastro, a rota de credencial responde:

```json
{
  "code": "PROVIDER_UNAVAILABLE",
  "message": "A origem do CRM não está configurada para esta instância",
  "statusCode": 503
}
```

Hoje, a ZapperHub faz o cadastro. Peça pelo suporte e informe a origem exata das
páginas que vão embutir o componente. Exemplo: `https://crm.suaempresa.com.br`,
ou `http://localhost:3000` para desenvolvimento.

Informe só esquema, domínio e porta, sem barra final e sem caminho. Use
`https://crm.suaempresa.com.br`, nunca `https://crm.suaempresa.com.br/` nem
`https://crm.suaempresa.com.br/atendimento`. A plataforma compara o valor com o
cabeçalho `Origin` do navegador. Com uma barra a mais, a credencial é emitida, e a
sessão é recusada depois com `AGENT_TOKEN_INVALID`.

Cada instância tem uma origem. Se o mesmo sistema atende vários domínios, fale com
o suporte antes de integrar.
</Warning>

## Passo 1: emitir a credencial

Chame esta rota a partir do seu backend, com a `x-api-key` da instância.

```http
POST /{instanceId}/softphone/tokens
```

```json
{
  "agentId": "op-1183",
  "displayName": "Ana"
}
```

| Campo | Obrigatório | Descrição |
| --- | --- | --- |
| `agentId` | Sim | Identificador do atendente no seu sistema. A plataforma não interpreta o valor. Aparece no histórico como autoria |
| `displayName` | Não | Nome exibido no histórico e para os outros atendentes quando a linha está ocupada |

Resposta:

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "expiresAt": "2026-09-09T18:15:00.000Z",
  "expiresIn": 900,
  "endpoint": "wss://server-03.zapperhub.com/softphone"
}
```

Devolva esse corpo ao navegador como veio. A biblioteca usa o `endpoint`.

<Note>
**A credencial vale 15 minutos.** A biblioteca renova a credencial em segundo
plano com o seu `getToken`. Uma conversa em andamento nunca cai por vencimento. A
renovação só afeta as operações seguintes.

A plataforma não guarda cadastro de atendentes e não autentica pessoas. Ela
armazena só o identificador e o nome que você informa.
</Note>

## Passo 2: incluir o componente

Com bundler:

```bash
npm install @zapperhub/softphone
```

```ts
import { createSoftphone } from '@zapperhub/softphone'
```

Sem bundler:

```html
<script src="https://cdn.jsdelivr.net/npm/@zapperhub/softphone@1/dist/softphone.global.js"></script>
<!-- disponível como ZapperSoftphone.createSoftphone -->
```

## Passo 3: criar o softphone

```ts
const softphone = createSoftphone({
  instanceId: 'inst_123',
  getToken: async () => {
    // a rota do SEU backend, do passo 1
    const r = await fetch('/api/softphone-token', { method: 'POST' })
    return r.json() // { token, expiresAt, endpoint }
  },
})
```

`createSoftphone` nunca lança exceção. Em um navegador sem suporte a áudio, ou em
uma página fora de HTTPS, ele devolve uma instância indisponível com o motivo. O
restante da página continua a funcionar:

```ts
if (softphone.status === 'unsupported') {
  console.warn('Softphone indisponível:', softphone.unsupportedReason)
}
```

## Comandos

| Método | Função |
| --- | --- |
| `call(jid, { record })` | Origina a chamada. Pede o microfone antes de discar |
| `answer({ record })` | Aceita a chamada recebida sinalizada |
| `reject()` | Recusa a chamada recebida sinalizada |
| `hangup()` | Encerra a conversa, ou cancela uma chamada que ainda toca |
| `mute()` / `unmute()` | Silencia e reativa o microfone, sem encerrar a chamada |
| `devices.list()` | Lista os microfones e as saídas de áudio disponíveis |
| `devices.select({ inputId, outputId })` | Seleciona os dispositivos e preserva a escolha entre carregamentos |
| `devices.testInput()` | Inicia o teste de captação. Devolve `{ stop }` |
| `connect()` / `disconnect()` | Abre e fecha a sessão manualmente |
| `destroy()` | Libera microfone, sessão e conexão |

Há duas leituras diretas: `softphone.line` (a linha está ocupada?) e
`softphone.muted`.

## Estados e eventos

```ts
softphone.on('call', (chamada) => {
  // renderize o estado na sua tela
})
```

| Evento | Conteúdo | Quando |
| --- | --- | --- |
| `status` | `{ status, reason? }` | A sessão muda de situação |
| `call` | `{ callId, state, direction, contact, recording?, endedReason? }` | A chamada muda de estado |
| `incoming` | `{ callId, contact }` | Uma chamada recebida começa a tocar |
| `incoming:cleared` | `{ callId, reason }` | A chamada recebida para de tocar |
| `line` | `{ busy, callId?, agent? }` | A linha da instância é ocupada ou liberada |
| `mic` | `{ muted }` | O microfone é silenciado ou reativado |
| `devices` | Lista de dispositivos | Um dispositivo é conectado ou desconectado |
| `level` | `{ level }` | Durante `devices.testInput()`, de 0 a 1 |
| `error` | `{ code, message }` | Qualquer recusa |

### Estados da chamada (`call.state`)

| Estado | Significado |
| --- | --- |
| `IDLE` | Nenhuma chamada em andamento |
| `DIALING` | O pedido saiu do navegador. A chamada ainda não existe. `callId` ausente |
| `RINGING` | O aparelho do contato está tocando |
| `ACTIVE` | Conversa estabelecida nos dois sentidos |
| `RECONNECTING` | O atendente perdeu a conexão. A chamada continua por 15 segundos |
| `ENDED` | Encerrada. Veja `endedReason` |

### Motivos de encerramento (`call.endedReason`)

| Valor | Significado |
| --- | --- |
| `BY_AGENT` | O atendente encerrou pelo componente |
| `BY_CONTACT` | O contato desligou |
| `REJECTED` | Recusada |
| `MISSED` | Não atendida |
| `UNAVAILABLE` | Contato indisponível, em outra ligação |
| `FAILED` | Falha: microfone revogado, período de graça esgotado ou queda da instância |

### Motivos de fim da sinalização (`incoming:cleared.reason`)

| Valor | Significado |
| --- | --- |
| `ANSWERED_ELSEWHERE` | Outro atendente aceitou. Situação normal, não erro |
| `REJECTED` | Um atendente recusou |
| `ABANDONED` | O contato desistiu antes de qualquer aceite |

## Vários atendentes na mesma instância

A instância conduz uma chamada por vez. Todos os atendentes conectados usam essa
linha.

- Uma chamada recebida toca em todos. O primeiro que aceita conduz. Os outros recebem `incoming:cleared` com `ANSWERED_ELSEWHERE`.
- Quando alguém ocupa a linha, os outros recebem `line` com `busy: true` e o nome de quem fala.
- Em dois pedidos ao mesmo tempo, exatamente um é aceito. O outro recebe `409 CALL_IN_PROGRESS`.

<Note>
`ANSWERED_ELSEWHERE` e `CALL_IN_PROGRESS` são o funcionamento normal com vários
atendentes. Mostre esses casos como informação ("atendida por outro atendente",
"linha ocupada"), não como falha.
</Note>

## Oscilação de conexão

Se o atendente perde a conexão, a chamada com o contato não cai na hora. A
plataforma espera 15 segundos.

- Reconexão dentro do prazo: a conversa continua na mesma chamada, com o mesmo `callId`, sem nova discagem.
- Prazo esgotado: a chamada termina com `FAILED`, e a linha é liberada.
- O contato desligou durante a espera: o desfecho é `BY_CONTACT`, não falha.

Fechar a aba do navegador segue a mesma regra.

## Gravação

Passe `record: true` ao originar ou ao atender. As regras (cota diária, limite de
duração, entrega por evento, link assinado e retenção) são as mesmas de
[Chamadas](/functions/calls).

```ts
const chamada = await softphone.call('5511999999999', { record: true })

if (chamada.recording?.requested && !chamada.recording.granted) {
  // a chamada ACONTECE; só não será gravada
  console.log('Sem gravação:', chamada.recording.reason)
}
```

<Warning>
**A cota diária não impede a chamada.** A chamada acontece sem gravação, e o
motivo chega em `recording.reason`. Avise o atendente no momento da discagem.

Informar ao contato que a ligação está sendo gravada é responsabilidade sua,
conforme a LGPD.
</Warning>

## Erros e ação recomendada

| Código | Quando | Ação |
| --- | --- | --- |
| `MICROPHONE_DENIED` | O atendente negou o microfone | Oriente a liberar o microfone pelo cadeado na barra de endereço e tentar de novo. Nenhuma chamada foi criada |
| `MICROPHONE_UNAVAILABLE` | Nenhum microfone, ou microfone em uso por outro programa | Peça para conectar o headset ou fechar o outro programa |
| `INSECURE_CONTEXT` | Página fora de HTTPS | Sirva a página por HTTPS. `localhost` conta como seguro |
| `UNSUPPORTED_ENVIRONMENT` | Navegador sem captura de áudio ou sem WebRTC | Oriente a usar Chrome, Edge, Firefox ou Safari recentes |
| `PROVIDER_UNAVAILABLE` | A origem do seu sistema não está cadastrada na instância | Peça o cadastro ao suporte, com a origem exata. Veja [Pré-requisitos](#pre-requisitos) |
| `AGENT_TOKEN_INVALID` | Credencial expirada, adulterada, desconhecida, ou apresentada por uma página de outra origem | Emita uma credencial nova pelo backend. Se persistir, confira se a origem cadastrada é igual à da página, sem barra final |
| `AGENT_TOKEN_SCOPE` | Credencial usada fora do escopo de chamadas | Defeito de integração. A credencial só serve ao softphone |
| `CALL_IN_PROGRESS` | A instância já conduz uma chamada | Mostre a linha como ocupada. `detail` traz o `callId` em andamento |
| `CALL_NOT_AVAILABLE` | A chamada já foi atendida por outro, ou já terminou | Mostre como informação, não como falha |
| `INVALID_CALL_TARGET` | O número não tem conta de WhatsApp | Confirme o número com o atendente |
| `INSTANCE_NOT_CONNECTED` | A instância perdeu a sessão do WhatsApp | Reconecte a instância no painel |
| `UNSUPPORTED_FOR_INSTANCE_TYPE` | Instância de conexão oficial | O softphone não existe para a Cloud API |
| `DEVICE_LOST` | O dispositivo selecionado foi desconectado | A chamada continua no dispositivo padrão. Atualize a lista de dispositivos na tela |
| `MEDIA_NEGOTIATION_FAILED` | O áudio não pôde ser estabelecido | Verifique a conexão do atendente e tente reconectar |
| `SESSION_CLOSED` | Comando enviado com a sessão fechada | Chame `connect()` antes, ou aguarde a reconexão automática |

## Histórico e autoria

As chamadas do softphone aparecem no [histórico de chamadas](/functions/calls)
com a autoria do atendente. Filtre por atendente:

```http
GET /{instanceId}/calls?agentId=op-1183
```

```json
{
  "callId": "...",
  "conductedVia": "SOFTPHONE",
  "agent": { "id": "op-1183", "displayName": "Ana" }
}
```

As chamadas originadas pela API aparecem com `"conductedVia": "API"` e sem o
campo `agent`.

## Compatibilidade

O softphone é outra forma de conduzir a mesma chamada. Se você já consome as
chamadas por API:

- Os eventos continuam em `calls.update`, com o mesmo formato.
- As rotas da API continuam disponíveis e inalteradas.
- O histórico ganhou campos novos. Nenhum campo existente mudou.

Uma instância sem atendente conectado se comporta como antes.
