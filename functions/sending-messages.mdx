## Descrição

Esta página descreve cada tipo de mensagem que a ZapperHub envia: a rota, os
campos, os limites e as diferenças entre uma instância oficial (Cloud API), uma
não oficial (`device`) e o Instagram. A referência completa de cada campo está na
[API Reference](/api-reference).

## Como o envio funciona

Todo envio passa pela [fila da instância](/definitions/queue). Por isso, a API
responde `200` com o agendamento, não com a entrega:

```json
{ "status": "scheduled", "jobId": "42" }
```

O resultado chega por webhook:

- `messages.upsert` quando a mensagem foi enviada.
- `messages.error` quando as tentativas se esgotaram.

Veja os [exemplos de payload](/integrations/webhooks).

Quando a falha vem da Meta (Cloud API), o `messages.error` mantém o código e o
texto originais. Para os códigos conhecidos, ele acrescenta
`error.localizedMessage` com a explicação em português. Exemplo: "A janela de 24h
com este cliente está fechada".

<Note>
**Exceção.** Reagir, marcar como lida e excluir não passam pela fila. A API
aplica a operação na hora e responde `204`, sem corpo e sem `jobId`.
</Note>

## O destinatário

Salvo onde indicado, o destinatário vai no campo `jid`:

| Formato | Exemplo |
| --- | --- |
| Número de telefone | `5512912345678` ou `5512912345678@s.whatsapp.net` |
| Identificador único do usuário (LID) | `123456789012345@lid` |
| Grupo | `120363012345678901@g.us` |
| Canal | `120363012345678901@newsletter` |

Informe o número completo, com o código do país. O prefixo `+` é opcional. Veja
[Formato do número](/definitions/number-format).

Na Cloud API, o destinatário também pode ser:

| Formato | Exemplo |
| --- | --- |
| BSUID do contato | `BR.13491208655302741918` |
| Username do WhatsApp | `fulano` ou `@fulano` |

A API resolve o username pelo vínculo guardado quando o contato escreveu para a
empresa: o telefone, se conhecido, ou o BSUID. Sem vínculo, a resposta é `404`
com `code: "CONTACT_NOT_FOUND"`. Veja
[Identidade do contato](/integrations/webhooks#identidade-do-contato-telefone-bsuid-e-username).

## Campos comuns

| Campo | Disponível em | Função |
| --- | --- | --- |
| `trackId` | Todos os envios enfileirados | Identificador seu, devolvido no webhook do envio. Não precisa ser único. |
| `trackSource` | Todos os envios enfileirados | Origem da mensagem (`crm`, `n8n`, …). Padrão: `api`. |
| `delay` | Texto, áudio, mídia | Atraso antes do envio, de 0 a 20 segundos. |
| `expiration` | Texto | Mensagem temporária: `none` (padrão), `24h`, `7d` ou `90d`. |
| `quotedMessageId` | Todos os envios enfileirados, inclusive template | Id da mensagem a citar. Veja [Responder citando uma mensagem](#responder-citando-uma-mensagem). |

## Responder citando uma mensagem

Para enviar uma mensagem como resposta a outra, informe em `quotedMessageId` o
id da mensagem citada. É o mesmo `key.id` que chega no webhook `messages.upsert`.
O campo é opcional e vale em todos os envios enfileirados.

```json
{
  "jid": "5512912345678",
  "message": "Sim, sai hoje às 14h.",
  "quotedMessageId": "wamid.HBgLNTUxMjkxMjM0NTY3OBUCABIYFjNFQjA"
}
```

A API responde `200` com o agendamento. O resultado da citação vem no
`messages.upsert` de saída, em `quote`:

```json
{
  "type": "messages.upsert",
  "key": { "fromMe": true, "id": "wamid.HBgL..." },
  "quote": { "id": "wamid.HBgLNTUxMjkxMjM0NTY3OBUCABIYFjNFQjA", "applied": true }
}
```

Quando a citação é aplicada, o conteúdo da mensagem traz `contextInfo` com
`stanzaId` e `participant`, no mesmo formato da citação que você recebe.

A citação nunca impede o envio. Se a citação não puder ser aplicada, a mensagem
sai sem citar, e o evento informa o motivo:

```json
{ "quote": { "id": "wamid.INEXISTENTE", "applied": false, "reason": "not_found" } }
```

| `reason` | Quando |
| --- | --- |
| `not_found` | A mensagem não está no histórico da instância (id errado, de outra instância ou de outra conversa), ou o autor dela não é conhecido |
| `unsupported_type` | O tipo de mensagem não aceita citação neste canal. No canal não oficial, botões e lista não citam |

<Note>
A busca da mensagem citada ocorre só no histórico da própria instância. O id de
uma mensagem de outra instância se comporta como um id inexistente.

Com `splitMessage` ou `processImageLink`, a mensagem vira várias. Só a primeira cita.
</Note>

Na Cloud API, a Meta aceita a citação em template, mas o aparelho do contato não
exibe a bolha de citação.

## Texto

`POST /{instanceId}/messages/text`

Só `message` é obrigatório. O destinatário vai em `jid` ou em `commentId`
(resposta privada a um comentário do Instagram). Informe exatamente um dos dois.

```json
{
  "jid": "5512912345678",
  "message": "Olá! Sua entrega sai hoje às 14h."
}
```

| Campo | Função |
| --- | --- |
| `mentions` | Números a mencionar. Só tem efeito em grupos. |
| `mentionsEveryone` | Menciona todos os participantes do grupo. Ignora `mentions`. |
| `splitMessage` | Divide a mensagem em várias, nas quebras de linha. |
| `processImageLink` | Envia os links de imagem do texto como imagem, logo após a mensagem. |
| `autoCaption` | Com `processImageLink` ativo, usa o texto da mensagem como legenda da imagem. |
| `showLinkPreview` | Exibe ou oculta a prévia do link. |
| `humanAgent` | Só Instagram. Veja [Responder em até 7 dias no Instagram](#responder-em-ate-7-dias-no-instagram). |

### Responder em até 7 dias no Instagram

Por padrão, o Instagram só permite responder até 24 horas depois da última
mensagem do contato. Com `humanAgent: true`, a API envia a mensagem como resposta
de um atendente humano, e a janela passa a 7 dias. O campo vale em
`messages/text`, `messages/media` e `messages/audio`. Os outros tipos de conexão
ignoram o campo.

```json
{
  "jid": "17841499999999999",
  "message": "Oi! Voltando ao seu pedido de ontem.",
  "humanAgent": true
}
```

<Warning>
**Regra da Meta.** Não use `humanAgent` em mensagens automáticas, como respostas
de bot ou disparos programados. Use só quando uma pessoa está respondendo. O app
da Meta precisa ter a permissão de atendimento humano aprovada. Sem ela, a janela
continua em 24 horas, e a Meta recusa o envio fora dela.
</Warning>

### Citar uma mensagem no Instagram

O `quotedMessageId` aceita o `mid` de uma mensagem do Instagram. A citação nunca
impede o envio. Se a citação não puder ser aplicada, a mensagem sai sem o balão de
citação.

Diferente do WhatsApp, o envio no Instagram não publica um `messages.upsert` de
saída com o campo `quote`. O eco da mensagem chega depois, pelo webhook da Meta,
com a citação em `contextInfo.stanzaId` quando ela foi aplicada.

## Mídia

`POST /{instanceId}/messages/media`

Imagem, vídeo, áudio e documento saem por esta rota. Escolha o tipo em
`mediaType`. O conteúdo vai em `media`, que aceita URL (`http`/`https`), base64 ou
data URL.

```json
{
  "jid": "5512912345678",
  "mediaType": "image",
  "media": "https://exemplo.com/nota-fiscal.png",
  "caption": "Sua nota fiscal"
}
```

| Campo | Observação |
| --- | --- |
| `mediaType` | `image`, `video`, `audio` ou `document` |
| `caption` | Legenda. Não se aplica a `audio`. |
| `filename` | Nome do arquivo. Só para `document`. |
| `mimetype` | Tipo MIME do arquivo, como `application/pdf`. Só para `document`. |

## Áudio (nota de voz)

`POST /{instanceId}/messages/audio`

Esta rota envia o áudio como nota de voz. A rota de mídia com
`mediaType: "audio"` envia o áudio como arquivo anexado.

```json
{
  "jid": "5512912345678",
  "audio": "https://exemplo.com/recado.mp3"
}
```

A rota aceita `mp3`, `mp4`, `wav` e `ogg`, por URL, base64 ou data URL.

## Áudio a partir de texto

`POST /{instanceId}/messages/text-to-speech`

A API converte o texto em áudio pela ElevenLabs e envia o áudio como nota de voz.
A rota exige a chave da ElevenLabs cadastrada em
`POST /{instanceId}/text-to-speech/key`.

```json
{
  "jid": "5512912345678",
  "text": "Seu pedido foi confirmado.",
  "voiceId": "21m00Tcm4TlvDq8ikWAM"
}
```

Sem `voiceId`, a API usa a voz padrão da instância. Veja
[Texto para fala](/painel/text-to-speech).

## Sticker

`POST /{instanceId}/messages/sticker`

```json
{
  "jid": "5512912345678",
  "sticker": "https://exemplo.com/figurinha.webp"
}
```

O arquivo deve ser `image/webp` ou `video/mp4`. A API recusa outros formatos.

## Localização

`POST /{instanceId}/messages/location`

```json
{
  "jid": "5512912345678",
  "location": {
    "name": "Loja Centro",
    "lat": -23.1791,
    "lon": -45.8872
  }
}
```

`lat` e `lon` são obrigatórios. `name` é opcional.

## Contato

`POST /{instanceId}/messages/contact`

O contato vai em campos estruturados no objeto `vcard`. A API converte o objeto
para vCard 3.0 antes do envio. Só `fn` (nome completo) é obrigatório.

```json
{
  "jid": "5512912345678",
  "name": "John Doe",
  "vcard": {
    "fn": "John Doe",
    "n": { "firstName": "John", "lastName": "Doe" },
    "tel": [{ "value": "+5512912345678", "type": ["cell"] }]
  }
}
```

## Botões

`POST /{instanceId}/messages/buttons`

A mensagem leva de 1 a 5 botões, de quatro tipos. Cada tipo exige um campo extra:

| `type` | Campo exigido | Efeito ao tocar |
| --- | --- | --- |
| `url` | `url` | Abre o endereço |
| `copy` | `copyCode` | Copia o valor |
| `call` | `phoneNumber` | Liga para o número |
| `reply` | `id` | Devolve o `id` como resposta rápida |

```json
{
  "jid": "5512912345678",
  "title": "Pedido #8823",
  "body": "Seu pedido saiu para entrega.",
  "footer": "Equipe ZapperHub",
  "buttons": [
    { "type": "reply", "id": "recebi", "displayText": "Recebi" },
    { "type": "url", "url": "https://exemplo.com/pedido/8823", "displayText": "Acompanhar" }
  ]
}
```

Todo botão tem `type`, `displayText` e `id`. Para enviar a mensagem com imagem ou
vídeo, use `media` e `mediaType`.

<Warning>
Botões de resposta rápida (`reply`) não são aceitos em grupos. A API recusa a
mensagem inteira com `400`.
</Warning>

A resposta do contato chega no webhook `messages.upsert`, em
`message.buttonsResponseMessage`.

## Lista de opções

`POST /{instanceId}/messages/list`

A mensagem de lista exibe um botão. Ao tocar no botão, o contato vê um menu com
até 10 opções, agrupadas em seções. Use a lista para oferecer um menu de
escolhas, como um cardápio, uma triagem ou uma agenda de horários.

A rota é a mesma para instâncias oficiais e não oficiais, e o corpo é idêntico.
A API aplica sempre os limites da Cloud API, para que o mesmo payload funcione em
qualquer instância.

```json
{
  "jid": "5512912345678",
  "buttonText": "Ver opções",
  "title": "Cardápio",
  "description": "Escolha uma das opções abaixo",
  "footer": "Equipe ZapperHub",
  "sections": [
    {
      "title": "Bebidas",
      "rows": [
        { "title": "Café", "description": "200ml", "rowId": "cafe-01" },
        { "title": "Suco", "description": "300ml", "rowId": "suco-01" }
      ]
    },
    {
      "title": "Comidas",
      "rows": [
        { "title": "Pão de queijo", "rowId": "pdq-01" }
      ]
    }
  ]
}
```

### Limites

| Campo | Obrigatório | Limite |
| --- | --- | --- |
| `buttonText` | Sim | 1 a 20 caracteres |
| `title` | Não | Até 60 caracteres |
| `description` | Sim | 1 a 1024 caracteres |
| `footer` | Não | Até 60 caracteres |
| `sections` | Sim | 1 a 10 seções |
| `sections[].title` | Condicional | Até 24 caracteres. Obrigatório a partir de 2 seções |
| `sections[].rows` | Sim | Ao menos 1 linha, e no máximo 10 linhas somadas todas as seções |
| `sections[].rows[].title` | Sim | 1 a 24 caracteres |
| `sections[].rows[].description` | Não | Até 72 caracteres |
| `sections[].rows[].rowId` | Sim | 1 a 200 caracteres. Único em toda a mensagem |

A API não trunca nada. Um valor acima do limite é recusado com `400`, e nenhuma
mensagem entra na fila.

<Warning>
Grupos só recebem lista em instância não oficial. A Cloud API não envia
mensagens de lista para grupos, e a API recusa a requisição com `400`.
</Warning>

Sem `title`, a instância não oficial mostra o cabeçalho padrão `Menu`. Na Cloud
API, a mensagem vai sem cabeçalho. Informe o `title` sempre que o cabeçalho
importar.

### Como receber a opção escolhida

O `rowId` da opção escolhida volta no webhook `messages.upsert`, em
`message.listResponseMessage.selectedButtonId`. O nome do campo é o mesmo nos
dois canais. Veja
[Escolha de opção em mensagem de lista](/integrations/webhooks#escolha-de-opcao-em-mensagem-de-lista).
Por isso o `rowId` deve ser único em toda a mensagem.

## Carrossel

`POST /{instanceId}/messages/carousel`

Disponível só em instâncias oficiais (Cloud API). Os outros tipos de conexão
respondem `422` com `code: "UNSUPPORTED_FOR_INSTANCE_TYPE"`. A mensagem leva de 2
a 10 cartões deslizáveis. Cada cartão tem uma imagem ou um vídeo, um texto
opcional e botões.

```json
{
  "jid": "5512912345678",
  "body": "Confira as ofertas da semana",
  "cards": [
    {
      "header": { "type": "image", "url": "https://exemplo.com/tenis.jpg" },
      "body": "Tênis de corrida",
      "buttons": [
        { "type": "reply", "id": "tenis-quero", "text": "Quero" },
        { "type": "reply", "id": "tenis-depois", "text": "Depois" }
      ]
    },
    {
      "header": { "type": "image", "url": "https://exemplo.com/bota.jpg" },
      "body": "Bota de trilha",
      "buttons": [
        { "type": "reply", "id": "bota-quero", "text": "Quero" },
        { "type": "reply", "id": "bota-depois", "text": "Depois" }
      ]
    }
  ]
}
```

A API responde `{ "status": "scheduled", "jobId": "..." }`, como nos demais
envios. `quotedMessageId`, `trackId` e `trackSource` valem como nos outros tipos.

### Regras de validação

A API confere as regras da Meta antes de enfileirar. Quando uma regra é violada,
a resposta é `400`, e `validation` traz o caminho do cartão (por exemplo,
`/cards/1/buttons`) com a explicação em português.

| Campo | Regra |
| --- | --- |
| `body` | Obrigatório, até 1024 caracteres |
| `cards` | De 2 a 10 cartões |
| `cards[].header` | `type` `image` ou `video`, com `url` pública. A API recusa outros formatos |
| `cards[].body` | Opcional, até 160 caracteres e 2 quebras de linha |
| `cards[].buttons` | Ou 1 botão `url`, ou de 1 a 2 botões `reply`. Não misture os dois no mesmo cartão |
| Botões entre cartões | Todos os cartões devem ter o mesmo tipo e a mesma quantidade de botões |
| `text` do botão | Até 20 caracteres |
| `id` do botão `reply` | Até 256 caracteres. A API não altera o valor |

A imagem ou o vídeo de cada cartão vai para a Meta como link, sem upload prévio.
Se a Meta não conseguir baixar uma mídia, o carrossel não é entregue. A mensagem
fica com status `failed` (webhook `messages.error`), com o motivo da Meta. A Meta
não informa qual cartão tinha o problema.

### Como receber o botão tocado

Quando o contato toca em um botão `reply`, chega um `messages.upsert` com
`message.buttonsResponseMessage`, no mesmo formato dos [botões](#botoes).
`contextInfo.stanzaId` traz o id do carrossel. `selectedButtonId` traz o `id` do
botão como você o definiu. Use ids únicos por cartão, como `tenis-quero`, para
saber de qual cartão veio o toque. Botões de URL abrem o link e não geram evento.

## Template

`POST /{instanceId}/messages/template`

Disponível só em instâncias oficiais (Cloud API). O template é o único tipo que
alcança um contato fora da janela de 24 horas. Ele exige um template aprovado
pela Meta. Crie o template pelo [painel](/painel/templates) ou por
`POST /{instanceId}/message-templates`.

```json
{
  "jid": "5512912345678",
  "templateName": "confirmacao_pedido",
  "language": "pt_BR",
  "components": [
    {
      "type": "body",
      "parameters": [{ "type": "text", "text": "8823" }]
    }
  ]
}
```

Informe em `components` só o que tem variáveis. Um template sem variáveis
dispensa o campo. Para saber se a janela com o contato está aberta, use
`GET /{instanceId}/check-message-window`.

### Consultar um template

`GET /{instanceId}/message-templates/{templateId}`

A rota consulta o template na Meta pelo `id` e atualiza a cópia guardada pela
API. Use a rota para acompanhar a revisão sem esperar o webhook.

```json
{
  "id": "1234567890",
  "name": "boas_vindas",
  "language": "pt_BR",
  "category": "MARKETING",
  "status": "REJECTED",
  "rejectedReason": "INVALID_FORMAT",
  "parameterFormat": "POSITIONAL",
  "components": [{ "type": "BODY", "text": "Olá {{1}}" }]
}
```

`rejectedReason` traz o motivo da Meta quando o template foi recusado. Nos outros
casos, vem `null`. O mesmo motivo chega no webhook de status do template.

Um `id` que não existe, ou que pertence a outra conta do WhatsApp Business,
responde `404` com `code: "TEMPLATE_NOT_FOUND"`.

### Editar um template

`PATCH /{instanceId}/message-templates/{templateId}`

O corpo usa o mesmo formato da
[criação](/api-reference/cloud-api/criar-template-de-mensagem): `header`, `body`,
`footer` e `buttons`. `category` é opcional.

<Warning>
A Meta substitui todos os componentes. Envie o conteúdo completo do template, não
só o trecho que mudou.
</Warning>

```json
{
  "body": { "text": "Olá {{1}}, seu pedido saiu para entrega.", "examples": ["Maria"] },
  "footer": { "text": "Responda SAIR para não receber mais" }
}
```

Só templates `APPROVED`, `REJECTED` ou `PAUSED` aceitam edição. Nos outros status
(`PENDING`, `IN_APPEAL`, `DISABLED`, `PENDING_DELETION`, `LOCKED`), a API
responde `422` com `code: "TEMPLATE_NOT_EDITABLE"` e o status em `data.status`,
sem chamar a Meta. Se a cópia local tem mais de 5 minutos, a API relê o status na
Meta antes de decidir.

Depois da edição, o template volta para revisão. A resposta é
`{ "id": "...", "status": "PENDING" }`. O template só pode ser enviado quando a
Meta aprovar de novo. Um cabeçalho de imagem ou vídeo informado por URL é enviado
à Meta e trocado pelo `header_handle`, como na criação.

A Meta limita quantas vezes um template pode ser editado em um período e recusa a
troca de categoria em template aprovado. Nesses casos, a resposta é `422` com
`code: "PROVIDER_REJECTED"`, o código original em `meta` e, para os códigos
conhecidos, o texto em português em `localizedMessage`.

### Excluir um template

`DELETE /{instanceId}/message-templates/{name}`

A rota exclui o template na Meta e responde `{ "success": true }`.

<Warning>
**Exclusão irreversível.** Sem o parâmetro `language`, a rota exclui o template
por nome e remove todas as versões de idioma de uma vez. A API não verifica nem
cancela envios pendentes que usem o template.
</Warning>

O `name` segue a regra da Meta: minúsculas, dígitos e underscore, até 512
caracteres.

Para excluir só um idioma, informe `language`:

`DELETE /{instanceId}/message-templates/{name}?language=pt_BR`

Os outros idiomas continuam na Meta e na cópia local. Um idioma que o template
não tem responde `404` com `code: "TEMPLATE_NOT_FOUND"`.

Três limitações vêm da Meta:

- Uma mensagem já enviada e ainda não entregue coloca o template em
  `PENDING_DELETION`. A Meta tenta a entrega por até 30 dias.
- Depois da exclusão de um template `APPROVED`, o mesmo nome fica bloqueado para
  recriação por 30 dias.
- Templates `DISABLED` não podem ser excluídos.

Repetir a exclusão de um template já removido responde `404`. A operação não é
idempotente. A exclusão também está no [painel](/painel/templates).

## Reagir a uma mensagem

`POST /{instanceId}/messages/react`

```json
{
  "remoteJid": "5512912345678@s.whatsapp.net",
  "id": "3AB16AB78CD9012E89A0",
  "text": "❤️"
}
```

A API responde `204`, sem corpo. Uma string vazia em `text` remove a reação. Só
emojis são aceitos.

A reação vale para instâncias não oficiais, para a Cloud API e para o Instagram.
Na Cloud API, `remoteJid` também aceita o BSUID do contato. No Instagram,
`remoteJid` é o id do contato, e `id` é o `mid` da mensagem.

No Instagram, a reação do contato chega no webhook `messages.upsert` como
`reactionMessage`. A retirada vem com `removed: true`. O `key.id` desse evento é
composto (`ig-reaction:<mid>:<remetente>:<timestamp>`), porque o Instagram não dá
id próprio à reação. A mensagem reagida está em `reactionMessage.key.id`.

<Note>
Na Cloud API, a Meta só entrega a reação a mensagens de até 30 dias, não
apagadas e que não são reações. Fora disso, a Meta aceita o pedido, e a reação
falha depois: o `messages.status` chega com `failed` e o código `131009`.
</Note>

Quando a Meta recusa o pedido na hora, a resposta traz o erro tipado:

| Status | `code` | Quando |
| --- | --- | --- |
| `422` | `PROVIDER_REJECTED` | A Meta recusou por uma regra conhecida. `meta` traz o código e o subcódigo. `localizedMessage` traz a explicação |
| `429` | `RATE_LIMITED` | Limite de taxa da Meta |
| `502` | `PROVIDER_ERROR` | Erro da Meta fora do catálogo. O código original vem em `meta` |
| `503` | `PROVIDER_UNAVAILABLE` | A Meta não respondeu |
| `422` | `UNSUPPORTED_FOR_INSTANCE_TYPE` | Tipo de conexão sem suporte a reação |

As reações recebidas chegam no webhook `messages.upsert`, como `reactionMessage`.
Veja os [exemplos de payload](/integrations/webhooks#recebimento-de-mensagens).

## Marcar como lida

`POST /{instanceId}/messages/read`

```json
{
  "remoteJid": "5512912345678@s.whatsapp.net",
  "ids": ["3AB16AB78CD9012E89A0", "3AB16AB78CD9012E89A1"]
}
```

A rota informa ao WhatsApp que mensagens recebidas foram lidas. O remetente vê
os dois checks azuis. A API responde `204`, sem corpo.

- `remoteJid` é a conversa. `ids` são os `key.id` das mensagens, como chegam no webhook `messages.upsert`.
- Em grupo, informe também `senderJid` com o autor das mensagens.
- A rota vale só para instâncias não oficiais.
- O efeito depende da privacidade da conta. Com a confirmação de leitura
  desligada, o WhatsApp não mostra os checks azuis ao remetente.

Para acompanhar a entrega e a leitura das mensagens que você enviou, assine o
webhook [`messages.status`](/integrations/webhooks#estado-de-entrega-da-mensagem).

## Excluir uma mensagem

`POST /{instanceId}/messages/delete`

```json
{
  "key": {
    "remoteJid": "5512912345678@s.whatsapp.net",
    "fromMe": true,
    "id": "3AB16AB78CD9012E89A0"
  }
}
```

Informe a `key` exatamente como recebida no webhook. `remoteJid` e `id`
identificam a mensagem. A API responde `204`, sem corpo.

A conta só pode excluir mensagens que ela mesma enviou. Em grupos, um
administrador pode excluir mensagens de outros participantes.
