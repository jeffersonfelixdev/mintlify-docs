Esta página detalha **cada tipo de mensagem** que a ZapperHub envia: a rota, os
campos que importam, os limites e o que muda entre uma instância oficial (Cloud
API) e uma não oficial. Para a referência completa de cada campo, consulte a
[documentação de referência da API](/api-reference).

## Como funciona o envio

Todo envio passa pela [fila da instância](/definitions/queue). Por isso a
resposta da API é `200` com o **agendamento**, e não com a entrega:

```json
{ "status": "scheduled", "jobId": "42" }
```

O que aconteceu de fato chega por webhook: `messages.upsert` quando a mensagem
foi enviada, `messages.error` quando as tentativas se esgotaram. Veja os
[exemplos de payload](/integrations/webhooks).

Quando a falha vem da Meta (Cloud API), o `messages.error` mantém o código e o
texto originais dela e, para os códigos conhecidos, acrescenta
`error.localizedMessage` com a explicação em português — por exemplo, "A janela
de 24h com este cliente está fechada". Códigos desconhecidos chegam sem esse
campo.

<Card title="EXCEÇÃO">
**Reagir** e **excluir** não passam pela fila: são aplicados na hora e respondem
`204`, sem corpo e sem `jobId`.
</Card>

## O destinatário

Salvo onde indicado, o destinatário vai no campo `jid` e aceita:

| Formato | Exemplo |
| --- | --- |
| Número de telefone | `5512912345678` ou `5512912345678@s.whatsapp.net` |
| Identificador único do usuário (LID) | `123456789012345@lid` |
| Grupo | `120363012345678901@g.us` |
| Canal | `120363012345678901@newsletter` |

O número deve estar no formato completo, com código do país; o prefixo `+` é
opcional. Veja [Formato dos números](/definitions/number-format).

Na **Cloud API**, o destinatário também pode ser:

| Formato | Exemplo |
| --- | --- |
| BSUID do contato | `BR.13491208655302741918` |
| Username do WhatsApp | `fulano` ou `@fulano` |

O username é resolvido pelo vínculo que a ZapperHub guardou quando o contato
escreveu para a empresa: o telefone, se for conhecido, ou o BSUID. Se não houver
vínculo, a resposta é `404` com `code: "CONTACT_NOT_FOUND"` — o contato precisa
ter escrito antes. Veja [Identidade do contato](/integrations/webhooks#identidade-do-contato-telefone-bsuid-e-username).

## Campos comuns

| Campo | Disponível em | O que faz |
| --- | --- | --- |
| `trackId` | todos os envios enfileirados | Identificador seu, devolvido no webhook do envio. Não precisa ser único |
| `trackSource` | todos os envios enfileirados | Origem da mensagem (`crm`, `n8n`, …). Padrão: `api` |
| `delay` | texto, áudio, mídia | Atraso antes do envio, de 0 a 20 segundos |
| `expiration` | texto | Mensagem temporária: `none` (padrão), `24h`, `7d` ou `90d` |
| `quotedMessageId` | todos os envios enfileirados, inclusive template | Id da mensagem a citar ("Responder"). Veja [Responder citando uma mensagem](#responder-citando-uma-mensagem) |

## Responder citando uma mensagem

Para que a mensagem saia como resposta a outra, informe em `quotedMessageId` o
id da mensagem que você quer citar — o mesmo `key.id` que chega no webhook
`messages.upsert`. O campo é opcional e vale em todos os envios enfileirados:
texto, mídia, áudio, sticker, localização, contato, botões, lista, carrossel,
texto para voz e template.

```json
{
  "jid": "5512912345678",
  "message": "Sim, sai hoje às 14h.",
  "quotedMessageId": "wamid.HBgLNTUxMjkxMjM0NTY3OBUCABIYFjNFQjA"
}
```

A resposta continua sendo `200` com o agendamento. O resultado da citação vem no
`messages.upsert` de saída, em `quote`:

```json
{
  "type": "messages.upsert",
  "key": { "fromMe": true, "id": "wamid.HBgL..." },
  "quote": { "id": "wamid.HBgLNTUxMjkxMjM0NTY3OBUCABIYFjNFQjA", "applied": true }
}
```

Quando a citação foi aplicada, o conteúdo da mensagem traz o `contextInfo` com
`stanzaId` e `participant`, no mesmo formato da citação que você recebe.

A citação **nunca impede o envio**. Se ela não puder ser aplicada, a mensagem
sai normalmente, sem citar, e o evento diz por quê:

```json
{ "quote": { "id": "wamid.INEXISTENTE", "applied": false, "reason": "not_found" } }
```

| `reason` | Quando acontece |
| --- | --- |
| `not_found` | A mensagem não está no histórico da instância — id errado, de outra instância ou de outra conversa — ou o autor dela não é conhecido |
| `unsupported_type` | O tipo de mensagem não aceita citação neste canal. No canal não oficial, **botões e lista** não citam |

<Card title="ATENÇÃO">
A busca da mensagem citada é feita **só no histórico da própria instância**. O id
de uma mensagem de outra instância se comporta como um id inexistente.

Com `splitMessage` ou `processImageLink`, a mensagem vira várias; **só a
primeira cita**.
</Card>

Na Cloud API, a Meta aceita a citação em template, mas o aparelho do contato não
exibe a bolha de citação nesse caso.

## Texto

`POST /{instanceId}/messages/text`

Só `message` é obrigatório — o destinatário vem em `jid` **ou** em `commentId`
(resposta privada a um comentário do Instagram), e exatamente um dos dois deve
estar presente.

```json
{
  "jid": "5512912345678",
  "message": "Olá! Sua entrega sai hoje às 14h."
}
```

Além do texto, a rota traz os recursos de composição:

| Campo | O que faz |
| --- | --- |
| `mentions` | Números a mencionar. Só tem efeito em grupos |
| `mentionsEveryone` | Menciona todos os participantes do grupo. Ignora `mentions` |
| `splitMessage` | Divide a mensagem em várias, usando as quebras de linha como corte |
| `processImageLink` | Envia os links de imagem do texto como imagem, logo após a mensagem |
| `autoCaption` | Com `processImageLink` ativo, usa o texto da mensagem como legenda da imagem |
| `showLinkPreview` | Exibe (ou não) o preview do link na mensagem |
| `humanAgent` | Só Instagram. Veja [Responder em até 7 dias no Instagram](#responder-em-ate-7-dias-no-instagram) |

### Responder em até 7 dias no Instagram

Por padrão, o Instagram só deixa responder até **24 horas** depois da última
mensagem do contato. Com `humanAgent: true`, a mensagem é enviada como resposta de
um atendente humano, e a janela passa a ser de **7 dias**. O campo vale em
`messages/text`, `messages/media` e `messages/audio`, e é ignorado nos outros tipos
de conexão.

```json
{
  "jid": "17841499999999999",
  "message": "Oi! Voltando ao seu pedido de ontem.",
  "humanAgent": true
}
```

<Card title="ATENÇÃO">
A política da Meta **proíbe** `humanAgent` em mensagens automáticas, como respostas
de bot ou disparos programados: use só quando uma pessoa estiver respondendo. O app
da Meta também precisa ter a permissão de atendimento humano aprovada; sem ela, a
janela continua sendo de 24 horas e o envio fora dela é recusado pela Meta.
</Card>

### Citar uma mensagem no Instagram

O `quotedMessageId` aceita o `mid` de uma mensagem do Instagram. A mensagem nunca
deixa de ser enviada por causa da citação: se ela não puder ser aplicada, a
mensagem sai normalmente, **sem** o balão de citação. Diferente do WhatsApp,
o envio do Instagram não publica um `messages.upsert` de saída com o campo `quote`:
o eco da mensagem enviada chega depois, pelo webhook da Meta, e traz a citação em
`contextInfo.stanzaId` quando ela foi aplicada.

## Mídia

`POST /{instanceId}/messages/media`

Imagem, vídeo, áudio e documento saem todos por esta rota, escolhidos em
`mediaType`. O conteúdo vai em `media`, que aceita **URL (http/https), base64 ou
data URL**.

```json
{
  "jid": "5512912345678",
  "mediaType": "image",
  "media": "https://exemplo.com/nota-fiscal.png",
  "caption": "Sua nota fiscal"
}
```

| Campo | Observação |
| --- | --- |
| `mediaType` | `image`, `video`, `audio` ou `document` |
| `caption` | Legenda. Não se aplica a `audio` |
| `filename` | Nome do arquivo. Só para `document` |
| `mimetype` | Mimetype do arquivo (ex.: `application/pdf`). Só para `document` |

## Áudio (nota de voz)

`POST /{instanceId}/messages/audio`

A diferença para `mediaType: "audio"` é a forma: esta rota envia como **nota de
voz**, aquela como arquivo de áudio anexado.

```json
{
  "jid": "5512912345678",
  "audio": "https://exemplo.com/recado.mp3"
}
```

Aceita `mp3`, `mp4`, `wav` e `ogg`, por URL, base64 ou data URL.

## Áudio a partir de texto

`POST /{instanceId}/messages/text-to-speech`

Converte o texto em áudio pela ElevenLabs e envia como nota de voz. Exige a chave
da ElevenLabs cadastrada em `POST /{instanceId}/text-to-speech/key`.

```json
{
  "jid": "5512912345678",
  "text": "Seu pedido foi confirmado.",
  "voiceId": "21m00Tcm4TlvDq8ikWAM"
}
```

Sem `voiceId`, é usada a voz padrão configurada na instância. Veja
[Text to Speech](/painel/text-to-speech).

## Sticker

`POST /{instanceId}/messages/sticker`

```json
{
  "jid": "5512912345678",
  "sticker": "https://exemplo.com/figurinha.webp"
}
```

O arquivo precisa estar em `image/webp` ou `video/mp4` — outros formatos são
recusados.

## Localização

`POST /{instanceId}/messages/location`

```json
{
  "jid": "5512912345678",
  "location": {
    "name": "Loja Centro",
    "lat": -23.1791,
    "lon": -45.8872
  }
}
```

`lat` e `lon` são obrigatórios; `name` é opcional.

## Contato

`POST /{instanceId}/messages/contact`

O contato vai em campos estruturados no objeto `vcard`, convertido para vCard 3.0
antes do envio. Só `fn` (nome completo) é obrigatório.

```json
{
  "jid": "5512912345678",
  "name": "John Doe",
  "vcard": {
    "fn": "John Doe",
    "n": { "firstName": "John", "lastName": "Doe" },
    "tel": [{ "value": "+5512912345678", "type": ["cell"] }]
  }
}
```

## Botões

`POST /{instanceId}/messages/buttons`

De 1 a 5 botões, de quatro tipos, cada um exigindo um campo extra:

| `type` | Campo exigido | Efeito ao tocar |
| --- | --- | --- |
| `url` | `url` | Abre o endereço |
| `copy` | `copyCode` | Copia o valor |
| `call` | `phoneNumber` | Liga para o número |
| `reply` | `id` | Devolve o `id` como resposta rápida |

```json
{
  "jid": "5512912345678",
  "title": "Pedido #8823",
  "body": "Seu pedido saiu para entrega.",
  "footer": "Equipe ZapperHub",
  "buttons": [
    { "type": "reply", "id": "recebi", "displayText": "Recebi" },
    { "type": "url", "url": "https://exemplo.com/pedido/8823", "displayText": "Acompanhar" }
  ]
}
```

Todo botão tem `type`, `displayText` e `id`. Para acompanhar a mensagem com
imagem ou vídeo, use `media` e `mediaType`.

<Card title="ATENÇÃO">
Botões de **resposta rápida** (`reply`) não são aceitos em grupos — a mensagem
inteira é recusada com `400`.
</Card>

A resposta do contato chega no webhook `messages.upsert`, em
`message.buttonsResponseMessage`.

## Lista de opções

`POST /{instanceId}/messages/list`

A mensagem de lista exibe um botão que, ao ser tocado, abre um menu com até 10
opções agrupadas em seções. É a forma de oferecer um menu de escolhas — um
cardápio, uma triagem de atendimento, uma agenda de horários — sem depender de o
contato digitar a resposta certa.

A rota é **única para instâncias oficiais e não oficiais**, e o corpo é idêntico
nos dois casos: aplicamos sempre os limites da Cloud API, para que o mesmo
payload funcione em qualquer instância.

```json
{
  "jid": "5512912345678",
  "buttonText": "Ver opções",
  "title": "Cardápio",
  "description": "Escolha uma das opções abaixo",
  "footer": "Equipe ZapperHub",
  "sections": [
    {
      "title": "Bebidas",
      "rows": [
        { "title": "Café", "description": "200ml", "rowId": "cafe-01" },
        { "title": "Suco", "description": "300ml", "rowId": "suco-01" }
      ]
    },
    {
      "title": "Comidas",
      "rows": [
        { "title": "Pão de queijo", "rowId": "pdq-01" }
      ]
    }
  ]
}
```

### Limites

| Campo | Obrigatório | Limite |
| --- | --- | --- |
| `buttonText` | Sim | 1 a 20 caracteres |
| `title` | Não | até 60 caracteres |
| `description` | Sim | 1 a 1024 caracteres |
| `footer` | Não | até 60 caracteres |
| `sections` | Sim | 1 a 10 seções |
| `sections[].title` | Condicional | até 24 caracteres — **obrigatório a partir de 2 seções** |
| `sections[].rows` | Sim | ao menos 1, e no máximo **10 linhas somadas todas as seções** |
| `sections[].rows[].title` | Sim | 1 a 24 caracteres |
| `sections[].rows[].description` | Não | até 72 caracteres |
| `sections[].rows[].rowId` | Sim | 1 a 200 caracteres, **único em toda a mensagem** |

Nada é truncado: o que exceder o limite é recusado com `400`, e nenhuma mensagem
entra na fila.

<Card title="ATENÇÃO">
**Grupos só recebem lista em instância não oficial**: a Cloud API não envia
mensagens de lista para grupos, e a requisição é recusada com `400`.
</Card>

Quando `title` é omitido, a instância não oficial mostra o cabeçalho padrão
`Menu`, enquanto na Cloud API a mensagem vai sem cabeçalho algum. Informe o
`title` sempre que o cabeçalho importar.

### Como recebo a opção escolhida

O identificador que você definiu em `rowId` volta no webhook `messages.upsert`,
em `message.listResponseMessage.selectedButtonId`, com o mesmo nome de campo nos
dois canais — veja [Escolha de opção em mensagem de
lista](/integrations/webhooks). Por isso o `rowId` deve ser único em toda a
mensagem: é ele que identifica, sem ambiguidade, o que a pessoa escolheu.

## Carrossel

`POST /{instanceId}/messages/carousel`

Exclusivo de instâncias oficiais (Cloud API); os outros tipos de conexão
respondem `422` com `code: "UNSUPPORTED_FOR_INSTANCE_TYPE"`. Envia de 2 a 10
cartões deslizáveis, cada um com uma imagem ou vídeo, um texto opcional e
botões.

```json
{
  "jid": "5512912345678",
  "body": "Confira as ofertas da semana",
  "cards": [
    {
      "header": { "type": "image", "url": "https://exemplo.com/tenis.jpg" },
      "body": "Tênis de corrida",
      "buttons": [
        { "type": "reply", "id": "tenis-quero", "text": "Quero" },
        { "type": "reply", "id": "tenis-depois", "text": "Depois" }
      ]
    },
    {
      "header": { "type": "image", "url": "https://exemplo.com/bota.jpg" },
      "body": "Bota de trilha",
      "buttons": [
        { "type": "reply", "id": "bota-quero", "text": "Quero" },
        { "type": "reply", "id": "bota-depois", "text": "Depois" }
      ]
    }
  ]
}
```

Responde `{ "status": "scheduled", "jobId": "..." }`, como os demais envios. O
`quotedMessageId`, o `trackId` e o `trackSource` valem como nos outros tipos.

### Regras de validação

A API confere as regras da Meta antes de enfileirar. Quando uma é violada, a
resposta é `400` e `validation` traz o caminho do cartão (por exemplo,
`/cards/1/buttons`), com a explicação em português.

| Campo | Regra |
| --- | --- |
| `body` | Obrigatório, até 1024 caracteres |
| `cards` | De 2 a 10 cartões |
| `cards[].header` | `type` `image` ou `video`, com `url` pública. Outros formatos são recusados |
| `cards[].body` | Opcional, até 160 caracteres e 2 quebras de linha |
| `cards[].buttons` | **Ou** 1 botão `url`, **ou** de 1 a 2 botões `reply`. Não misture os dois no mesmo cartão |
| Botões entre cartões | Todos os cartões devem ter o **mesmo tipo** de botão e a **mesma quantidade** |
| `text` do botão | Até 20 caracteres |
| `id` do botão `reply` | Até 256 caracteres. É seu, e a API não o altera |

A API aceita até 2 respostas rápidas por cartão.

A imagem ou o vídeo de cada cartão vai para a Meta como link, sem upload prévio.
Se a Meta não conseguir baixar uma mídia, o carrossel não é entregue e a mensagem
fica com status `failed` (webhook `messages.error`), com o motivo da Meta. A Meta
não informa qual cartão tinha o problema, então a API também não informa.

### Como recebo o botão tocado

Quando o contato toca num botão `reply`, chega um `messages.upsert` com
`message.buttonsResponseMessage`, no mesmo formato dos [botões](#botões). O
`contextInfo.stanzaId` traz o id do carrossel, que permite ligar a resposta ao
envio, e `selectedButtonId` traz o `id` do botão como você o definiu — use ids
únicos por cartão (como `tenis-quero` acima) para saber de qual cartão veio o
toque. Botões de URL abrem o link e não geram evento.

## Template

`POST /{instanceId}/messages/template`

Exclusivo de instâncias oficiais (Cloud API). É o único tipo que alcança um
contato **fora da janela de 24 horas**, e exige um template previamente aprovado
pela Meta — crie pelo [painel](/painel/templates) ou por
`POST /{instanceId}/message-templates`.

```json
{
  "jid": "5512912345678",
  "templateName": "confirmacao_pedido",
  "language": "pt_BR",
  "components": [
    {
      "type": "body",
      "parameters": [{ "type": "text", "text": "8823" }]
    }
  ]
}
```

Informe em `components` apenas o que tem variáveis: um template sem variáveis
dispensa o campo. Para saber se ainda há janela aberta com o contato, use
`GET /{instanceId}/check-message-window`.

### Consultar um template

`GET /{instanceId}/message-templates/{templateId}`

Consulta o template na Meta pelo `id` (o mesmo devolvido na criação e na
listagem) e atualiza a cópia guardada pela API. Serve para acompanhar a revisão
sem esperar o webhook:

```json
{
  "id": "1234567890",
  "name": "boas_vindas",
  "language": "pt_BR",
  "category": "MARKETING",
  "status": "REJECTED",
  "rejectedReason": "INVALID_FORMAT",
  "parameterFormat": "POSITIONAL",
  "components": [{ "type": "BODY", "text": "Olá {{1}}" }]
}
```

`rejectedReason` traz o motivo informado pela Meta quando o template foi
recusado, e vem `null` nos demais casos. O mesmo motivo chega no webhook de
status do template e fica guardado na cópia local.

Um `id` que não existe, ou que pertence a outra conta do WhatsApp Business,
responde `404` com `code: "TEMPLATE_NOT_FOUND"`.

### Editar um template

`PATCH /{instanceId}/message-templates/{templateId}`

O corpo usa o mesmo formato da [criação](/api-reference/cloud-api/criar-template-de-mensagem)
(`header`, `body`, `footer`, `buttons`), e `category` é opcional. A Meta
**substitui todos os componentes**: envie o conteúdo completo do template, não
só o trecho que mudou.

```json
{
  "body": { "text": "Olá {{1}}, seu pedido saiu para entrega.", "examples": ["Maria"] },
  "footer": { "text": "Responda SAIR para não receber mais" }
}
```

Só templates `APPROVED`, `REJECTED` ou `PAUSED` aceitam edição. Nos demais status
(`PENDING`, `IN_APPEAL`, `DISABLED`, `PENDING_DELETION`, `LOCKED`) a API responde
`422` com `code: "TEMPLATE_NOT_EDITABLE"` e o status em `data.status`, **sem
chamar a Meta**. Se a cópia local tiver mais de 5 minutos, a API relê o status na
Meta antes de decidir.

Depois de editado, o template volta para revisão: a resposta é
`{ "id": "...", "status": "PENDING" }` e ele só pode ser enviado quando a Meta
aprovar de novo. Cabeçalho de imagem ou vídeo informado por URL é enviado à Meta
e trocado pelo `header_handle`, como na criação.

A Meta limita quantas vezes um template pode ser editado num período e recusa a
troca de categoria em template aprovado. Nesses casos a resposta é `422` com
`code: "PROVIDER_REJECTED"`, o código original em `meta` e, quando a API conhece o
código, o texto em português em `localizedMessage`.

### Excluir um template

`DELETE /{instanceId}/message-templates/{name}`

Exclui o template na Meta e responde `{ "success": true }`. Sem o parâmetro
`language`, a exclusão é **por nome** e remove **todas as versões de idioma** do
template de uma vez. É irreversível — envios pendentes que usem o template não
são verificados nem cancelados. O `name` segue a regra da Meta: minúsculas,
dígitos e underscore, até 512 caracteres.

Para excluir **só um idioma**, informe `language`:

`DELETE /{instanceId}/message-templates/{name}?language=pt_BR`

Os demais idiomas do nome continuam na Meta e na cópia local. Um idioma que o
template não tem responde `404` com `code: "TEMPLATE_NOT_FOUND"`.

Três limitações vêm da própria Meta: uma mensagem já enviada e ainda não
entregue coloca o template em `PENDING_DELETION`, com a entrega sendo tentada
por até 30 dias; depois de excluir um template `APPROVED`, o mesmo nome fica
bloqueado para recriação por 30 dias; e templates `DISABLED` não podem ser
excluídos.

Repetir a exclusão de um template já removido responde `404` — a operação não é
idempotente. Excluir também pelo [painel](/painel/templates).

## Reagir a uma mensagem

`POST /{instanceId}/messages/react`

```json
{
  "remoteJid": "5512912345678@s.whatsapp.net",
  "id": "3AB16AB78CD9012E89A0",
  "text": "❤️"
}
```

Responde `204`, sem corpo. Uma string vazia em `text` **remove** a reação
existente. Só emojis funcionam.

A reação vale para instâncias **não oficiais**, para a **Cloud API** e para o
**Instagram**. Na Cloud API, o `remoteJid` também aceita o BSUID do contato. No
Instagram, o `remoteJid` é o id do contato e o `id` é o `mid` da mensagem
reagida; o emoji vai como está, e a string vazia retira a reação.

No Instagram, a reação do contato também chega no webhook `messages.upsert`, como
`reactionMessage`, e a retirada vem com `removed: true`. O `key.id` desse evento
é composto (`ig-reaction:<mid>:<remetente>:<timestamp>`), e não o `mid`: o Instagram
não dá id próprio à reação, e usar o `mid` da mensagem reagida sobrescreveria a
mensagem original no histórico. A mensagem reagida está em `reactionMessage.key.id`.

<Card title="ATENÇÃO">
Na Cloud API, a Meta só entrega a reação a mensagens de **até 30 dias** que não
foram apagadas e não são, elas mesmas, reações. Fora disso, ela aceita o pedido e
a reação falha depois: o `messages.status` chega com `failed` e o código `131009`.
</Card>

Quando a Meta recusa o pedido na hora, a resposta traz o erro tipado, com o código
original em `meta` e, para os códigos conhecidos, a explicação em português:

| Status | `code` | Quando |
| --- | --- | --- |
| `422` | `PROVIDER_REJECTED` | A Meta recusou por uma regra conhecida. `meta` traz o código e o subcódigo, e `localizedMessage` a explicação |
| `429` | `RATE_LIMITED` | Limite de taxa da Meta |
| `502` | `PROVIDER_ERROR` | Erro da Meta fora do catálogo; o código original vem em `meta` |
| `503` | `PROVIDER_UNAVAILABLE` | A Meta não respondeu |
| `422` | `UNSUPPORTED_FOR_INSTANCE_TYPE` | Tipo de conexão sem suporte a reação |

As reações **recebidas** chegam no webhook `messages.upsert`, como
`reactionMessage` — veja os [exemplos de payload](/integrations/webhooks#recebimento-de-mensagens).

## Marcar como lida

`POST /{instanceId}/messages/read`

```json
{
  "remoteJid": "5512912345678@s.whatsapp.net",
  "ids": ["3AB16AB78CD9012E89A0", "3AB16AB78CD9012E89A1"]
}
```

Avisa o WhatsApp de que mensagens **recebidas** foram lidas: o remetente passa a
ver os dois checks azuis. Responde `204`, sem corpo.

- `remoteJid` é a conversa; `ids` são os `key.id` das mensagens, como chegam no
  webhook `messages.upsert`.
- Em **grupo**, informe também `senderJid` com quem escreveu as mensagens.
- Vale só para instâncias **não oficiais**. O efeito depende da configuração de
  privacidade da própria conta: com a confirmação de leitura desligada, o
  WhatsApp não mostra os checks azuis ao remetente.

Para acompanhar a entrega e a leitura das mensagens que **você enviou**, assine
o webhook [`messages.status`](/integrations/webhooks#estado-de-entrega-da-mensagem).

## Excluir uma mensagem

`POST /{instanceId}/messages/delete`

```json
{
  "key": {
    "remoteJid": "5512912345678@s.whatsapp.net",
    "fromMe": true,
    "id": "3AB16AB78CD9012E89A0"
  }
}
```

Informe a `key` exatamente como recebida no webhook — `remoteJid` e `id` são o
que identifica a mensagem. Responde `204`, sem corpo. Só é possível excluir
mensagens enviadas pela própria conta conectada ou, em grupos, sendo
administrador.
