## Descrição

As rotas de grupo estão disponíveis só para instâncias conectadas por QR Code.
Uma instância de outro tipo recebe `422` com o código
`UNSUPPORTED_FOR_INSTANCE_TYPE`.

## Operações

A API permite estas operações em grupos:

- Criar um grupo.
- Listar os grupos de que o número participa.
- Consultar os detalhes e os participantes de um grupo.
- Alterar o nome e a descrição de um grupo.
- Alterar e remover a foto de um grupo.
- Adicionar e remover participantes.
- Promover um participante a administrador e remover essa permissão.
- Obter o link de convite.
- Redefinir o link de convite.
- Alterar as configurações do grupo.
- Listar, aprovar e recusar pedidos de entrada.
- Consultar um convite sem entrar no grupo.
- Entrar em um grupo pelo convite.
- Sair de um grupo.

As rotas estão na seção *Grupos* da [API Reference](/api-reference).

Para comunidades, veja [Comunidades](/functions/communities).

Para enviar texto e mídia a um grupo, use as rotas de
[Envio de mensagens](/functions/sending-messages) com o JID do grupo em `jid`.

## Criar um grupo

Informe o nome e ao menos um participante. A conta conectada é a criadora e a
primeira administradora do grupo.

A resposta tem dois campos:

- `group`: os dados do grupo novo, com o JID em `id`. A lista `participants`
  tem só quem entrou no grupo.
- `participants`: o resultado de cada participante pedido. Veja
  [Resultado por participante](#resultado-por-participante).

O WhatsApp cria o grupo mesmo quando recusa uma parte dos participantes.

## Resultado por participante

O WhatsApp aceita ou recusa cada participante separadamente. A criação do
grupo, a rota de participantes e a aprovação de pedidos de entrada respondem
com uma lista que tem um item por participante:

| Campo | Descrição |
|---|---|
| `id` | JID ou LID do participante. Em grupos que usam LID, o valor pode ser o LID mesmo quando o pedido usou o número. |
| `phoneNumber`, `lid` | Número e LID do participante, quando o WhatsApp informa. Use estes campos para relacionar o item ao pedido. |
| `success` | `true` quando a ação valeu para o participante. |
| `error` | Código (`code`) e motivo (`reason`) da recusa. Só aparece quando `success` é `false`. |
| `invite` | Código do convite e validade (`expiresAt`, em epoch ms). Só aparece quando o motivo é `invite_required`. |

Os motivos mais comuns são:

| `reason` | Código | Significado |
|---|---|---|
| `invite_required` | 403 | A privacidade do participante só permite entrar por convite. Envie a ele o link de convite do grupo. |
| `invalid_phone_number` | 404 | O número não tem WhatsApp. |
| `temporarily_blocked` | 408 | O participante saiu do grupo há pouco tempo. |
| `conflict` | 409 | Ao adicionar, o participante já está no grupo. |
| `group_full` | 419 | O grupo atingiu o limite de participantes. |

Um código fora desta lista vem com o motivo `unknown`.

<Note>
A rota de participantes responde `200` mesmo quando o WhatsApp recusa todos os
participantes. Verifique `success` em cada item.
</Note>

## Alterar o nome e a descrição

Envie `name`, `description` ou os dois. Quando o corpo tem os dois campos, a API
altera o nome primeiro.

<Warning>
Se a alteração da descrição falhar, o nome novo fica gravado. Consulte o grupo
para ver o estado atual antes de enviar a alteração de novo.
</Warning>

## Redefinir o link de convite

<Warning>
Quando você redefine o link de convite, o link anterior deixa de funcionar.
</Warning>

A resposta tem o link novo em `inviteLink`.

## Alterar as configurações

Envie uma ou mais destas configurações:

| Campo | Efeito |
|---|---|
| `announce` | `true`: só administradores enviam mensagens. |
| `restrict` | `true`: só administradores alteram nome, descrição e foto. |
| `joinApprovalMode` | `true`: quem entra pelo link de convite precisa da aprovação de um administrador. |
| `ephemeralDuration` | Mensagens temporárias, em segundos: `0` (desligadas), `86400` (24 horas), `604800` (7 dias) ou `7776000` (90 dias). |

A API aplica as configurações nesta ordem: `announce`, `restrict`,
`joinApprovalMode`, `ephemeralDuration`.

<Warning>
Se uma configuração falhar, as configurações anteriores ficam gravadas.
Consulte o grupo para ver o estado atual antes de enviar a alteração de novo.
</Warning>

## Pedidos de entrada

Quando `joinApprovalMode` é `true`, quem usa o link de convite envia um pedido de
entrada. Para tratar os pedidos:

<Steps>
  <Step title="Listar os pedidos">
    Envie `GET /{instanceId}/groups/{groupId}/requests`. A resposta tem o `id` de
    cada pedido pendente.
  </Step>
  <Step title="Aprovar ou recusar">
    Envie `PATCH /{instanceId}/groups/{groupId}/requests` com os `id` em
    `participants` e `approve` ou `reject` em `action`.
  </Step>
</Steps>

A resposta tem o resultado de cada pedido. Veja
[Resultado por participante](#resultado-por-participante).

## Entrar em um grupo pelo convite

Informe o link de convite ou só o código em `invite`.

Para ver os dados do grupo antes de entrar, envie
`GET /{instanceId}/groups/invite-info?invite=<link ou código>`. Esta consulta não
faz a conta entrar no grupo.

Para entrar, envie `POST /{instanceId}/groups/join`. A resposta tem dois campos:

- `groupId`: o JID do grupo.
- `pendingApproval`: `true` quando o grupo exige aprovação. Nesse caso, a conta
  só entra no grupo depois que um administrador aprova o pedido.

## Sair de um grupo

<Warning>
Depois de sair, a conta só volta ao grupo com um convite ou quando um
administrador a adiciona.
</Warning>

Envie `POST /{instanceId}/groups/{groupId}/leave`.

## Recusa do WhatsApp

Algumas operações exigem que a conta conectada seja administradora do grupo.
Por exemplo: mudar participantes, obter o link de convite, alterar as
configurações, tratar pedidos de entrada e, em grupos com edição restrita,
alterar nome, descrição e foto.

Quando o WhatsApp recusa a operação, a API responde `422` com o código
`PROVIDER_REJECTED`. O motivo está em `detail`.

<Note>
Se o número conectado não é administrador do grupo, a Meta pode ocultar o
telefone dos participantes. Nesse caso, a API mostra o LID do contato no lugar
do número.
</Note>
