## Descrição

Na Cloud API, a ZapperHub guarda, para cada contato que escreve para a empresa:

- O vínculo entre **telefone**, **BSUID** e **username**.
- A escolha do contato sobre receber **mensagens de marketing**.

As rotas desta página consultam e alteram esses dados.

<Note>
**Escopo dos dados.** Os dados pertencem à empresa (WABA), não a um número. Todas
as suas instâncias na mesma WABA compartilham o vínculo e o opt-out. Outro dono
nunca vê esses dados, mesmo com a mesma WABA. O dono e a WABA vêm da instância da
`x-api-key`.
</Note>

| Rotas | Tipos de instância |
|---|---|
| Consulta, opt-out e exclusão | Só Cloud API |
| Bloqueio e desbloqueio | Cloud API e aparelho (`device`) |

Em um tipo de instância sem suporte, a resposta é `422` com
`code: "UNSUPPORTED_FOR_INSTANCE_TYPE"`.

## Identificar o contato

Em todas as rotas, o parâmetro `:contact` aceita:

| Formato | Exemplo |
| --- | --- |
| Telefone | `5512912345678`, com ou sem `+` e com ou sem `@s.whatsapp.net` |
| BSUID | `BR.13491208655302741918` |
| Username | `fulano` ou `@fulano` |

A API só reconhece um username se o contato já escreveu para a empresa.

## Consultar um contato

`GET /{instanceId}/contacts/{contact}`

```json
{
  "phone": "5512912345678",
  "waId": "5512912345678",
  "bsuid": "BR.13491208655302741918",
  "parentBsuid": null,
  "username": "fulano",
  "lastSeenAt": "2026-10-14T10:00:00.000Z",
  "marketing": {
    "status": "opted_out",
    "source": "meta",
    "changedAt": "2026-10-10T13:22:00.000Z"
  }
}
```

- `marketing` é `null` quando não há escolha registrada.
- Um contato desconhecido responde `404` com `code: "CONTACT_NOT_FOUND"`.
- Depois de uma [exclusão de dados](#excluir-os-dados-de-um-contato-lgpd) com
  opt-out ativo, só `marketing` vem preenchido. Os campos de identidade vêm `null`.

## Bloquear e desbloquear

Um contato bloqueado não consegue falar com o número da instância. As rotas
valem para a Cloud API e para o aparelho (`device`), com o mesmo contrato.

`POST /{instanceId}/contacts/block`
`POST /{instanceId}/contacts/unblock`

Requisição:

```json
{ "contact": "5512912345678" }
```

Resposta:

```json
{ "contact": "5512912345678", "blocked": true }
```

`blocked` é o estado final: `true` depois de bloquear, `false` depois de
desbloquear. Repetir a operação responde `200`.

| | Cloud API | Aparelho (`device`) |
| --- | --- | --- |
| Quem pode ser bloqueado | Quem enviou mensagem nas últimas 24 horas | Qualquer contato |
| Como informar o contato | Telefone, BSUID ou username | Só o telefone |
| Contato inválido | `404` se o username não tem vínculo | `400` para BSUID e username |

<Note>
**Regra da Meta.** Na Cloud API, só é possível bloquear quem enviou mensagem para
a empresa nas últimas 24 horas. Fora disso, a resposta é `422` com
`code: "PROVIDER_REJECTED"` e `localizedMessage` com a regra. Desbloquear não tem
essa restrição.
</Note>

Os erros da Meta chegam com o código e o subcódigo originais em `meta`. Para os
códigos conhecidos, `localizedMessage` traz a explicação em português. Exemplos:
lista cheia (64 mil bloqueados) e bloqueio do próprio número. Limite de taxa
responde `429`. Falha da Meta fora do catálogo responde `502`. Meta fora do ar
responde `503`.

### Listar os bloqueados

`GET /{instanceId}/contacts/blocked?limit=20&cursor=...`

```json
{
  "data": [
    { "contact": "5512912345678", "waId": "5512912345678" }
  ],
  "next": "eyJhIjoiQVFE..."
}
```

A API consulta a lista no provedor: a Meta na Cloud API, o aparelho no `device`.
A ZapperHub não guarda uma cópia.

- `limit` vai de 1 a 100.
- Para a próxima página, envie o `next` recebido em `cursor`. `next: null` indica a última página.
- `waId` só aparece na Cloud API.
- No aparelho, `contact` é o telefone. Um identificador que não é telefone, como um LID, aparece como veio.
- Se a lista mudar durante a paginação na Cloud API, a resposta é `409` com
  `code: "BLOCKLIST_CHANGED"`. Recomece a listagem.
- Um `cursor` inválido responde `400` com `code: "INVALID_CURSOR"`.

## Opt-out de marketing

Quando o contato pede para parar de receber marketing, ou volta a aceitar, a
Meta avisa a ZapperHub. A ZapperHub guarda a escolha e publica o evento
[`contacts.preference`](/integrations/webhooks#opt-out-de-marketing) em todas as
suas instâncias na WABA.

Enquanto o contato está em opt-out, a API recusa o envio de um **template de
marketing** antes de chegar à Meta:

```json
{
  "message": "O contato pediu para não receber mensagens de marketing desta empresa. Use um template de utilidade ou espere o contato voltar a aceitar marketing.",
  "error": "Application Error",
  "statusCode": 422,
  "code": "MARKETING_OPT_OUT",
  "data": { "optedOutAt": "2026-10-10T13:22:00.000Z", "source": "meta" }
}
```

- Templates de utilidade e de autenticação continuam a ser enviados.
- Quando o contato volta a aceitar marketing, a API volta a aceitar o envio.
- O opt-out vale pelo telefone e pelo BSUID do mesmo contato.
- Se a API não conhece a categoria do template, o envio segue. A Meta decide e
  recusa com o código `131050`.

### Listar os contatos em opt-out

`GET /{instanceId}/contacts/marketing-opt-outs?limit=20&cursor=...`

```json
{
  "data": [
    { "contact": "5512912345678", "source": "meta", "changedAt": "2026-10-10T13:22:00.000Z" }
  ],
  "next": null
}
```

A lista vem do mais recente para o mais antigo. `limit` vai de 1 a 100. Para a
próxima página, envie o `next` recebido em `cursor`. `next: null` indica a última
página. Um `cursor` inválido responde `400` com `code: "INVALID_CURSOR"`.

### Marcar ou desmarcar manualmente

`PUT /{instanceId}/contacts/{contact}/marketing-preference`

```json
{ "status": "opted_out" }
```

Use esta rota quando o contato pede por outro canal, como telefone ou e-mail,
para não receber marketing. `status` é `opted_out` (bloqueia marketing) ou
`opted_in` (libera). A resposta traz `source: "manual"` e a hora da mudança.

- Vale para todas as instâncias do mesmo dono na mesma WABA. Elas recebem o evento `contacts.preference`.
- Entre a escolha manual e um evento da Meta, vale a mais recente.
- A API aceita um contato que a ZapperHub nunca viu, se informado por telefone ou
  BSUID. Assim, você marca o opt-out antes de o contato escrever. Um username
  desconhecido responde `404`.
- Repetir a mesma escolha responde `200` e não publica o evento de novo.

## Excluir os dados de um contato (LGPD)

`DELETE /{instanceId}/contacts/{contact}`

A rota apaga o vínculo (telefone, BSUID e username) e a escolha de marketing do
contato. Responde `204`, sem corpo.

<Warning>
**O opt-out ativo é mantido**, reduzido ao identificador mínimo. Apagar o
opt-out reabriria o envio de marketing a quem pediu para sair. Se o contato
voltar a escrever, a ZapperHub recria o vínculo, e o opt-out continua a valer.
</Warning>

- Um contato desconhecido também responde `204`. A API não revela se o contato existia.
- A rota não publica evento.
- Quando uma WABA fica sem instância Cloud API, uma rotina diária apaga os dados do dono nessa WABA.
