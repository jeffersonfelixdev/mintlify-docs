## Description

The integrations screen (`dash/instances/[id]/integrations`) has two independent
tabs: **AI Agents** and **Chatwoot**. Each tab connects the
instance to a different service. Both can coexist.

## AI agents tab

Links the instance to an agent that answers the conversations automatically.

| Field | Required | Validation |
|---|---|---|
| **Integration type** | Yes | **Chatvolt**, **GPT Maker**, or **Zaia**. Error: *Integration type is required* |
| **Agent ID** | Yes | Error: *Agent ID is required* |
| **API Key** | Yes | Error: *API key is required* |

<Note>
New integrations accept only **Chatvolt**. GPT Maker and Zaia continue to work
for already registered integrations. See [AI agents](/en/integrations/ai-agents).
</Note>

After creation, change the integration with **Update** and remove
it with **Delete Integration**. Results: *Integration created successfully.*, *Integration deleted successfully.* and, on failure,
*An error occurred while deleting the integration. Please try again later.*

### Control the agent

The panel shows the section **How to control the agent**, with two commands sent in the conversation itself:

| Command | Effect |
|---|---|
| `#on` | Turns the AI on in the conversation |
| `#off` | Turns the AI off in the conversation |

The commands apply per conversation. Turning off the AI for one contact does not
affect the others. A human agent takes over one conversation without changing the
configuration.

See also the option **Disable AI on messages from device** in [Instance settings](/en/panel/instance-settings).
It turns off the AI in the conversation when the line owner replies from the phone.

### Follow-up webhook

For **Chatvolt** agents, the section **Webhook for follow-up and note messages** shows the URL to configure at
Chatvolt. Configure the webhook of the Chatvolt agent with this URL to send the
follow-up messages and the note messages. The copy button confirms with *URL copied successfully*.

The agent behavior is in [AI agents](/en/integrations/ai-agents). The grouping of
messages sent to the agent is the **Debounce**, in
[Instance settings](/en/panel/instance-settings).

## Chatwoot tab

<Warning>
**Beta.** This feature can change without notice. Errors or unexpected behavior
can occur.
</Warning>

The tab has two states: **New Chatwoot integration**, with no integration, and **Active integration**,
after creation.

### Create

| Field | Required | Validation |
|---|---|---|
| **Chatwoot URL** | Yes | Valid URL, such as `https://app.chatwoot.com`. Errors: *URL is required*, *Invalid URL* |
| **Account ID** | Yes | Numeric. Error: *Invalid account ID* |
| **Access token** | Yes | The Chatwoot API access token. Error: *Access token is required* |
| **Inbox name** | Yes | The name shown in Chatwoot. Error: *Inbox name is required* |
| **Show agent name in messages** | No | On or off |

With **Show agent name in messages** on, the name of the Chatwoot agent is
included in the messages sent to WhatsApp. The customer sees who is talking to
them.

Click **Create integration**. Success: *Chatwoot integration created successfully.* Failure: *Could not create the Chatwoot integration.*

### Generated identifiers

After creation, the panel shows three identifiers, generated by ZapperHub and by
Chatwoot:

| Identifier | Content |
|---|---|
| **Integration ID** | Identifies the integration in ZapperHub |
| **Inbox ID** | The inbox created in Chatwoot |
| **Webhook ID** | The webhook created in Chatwoot to receive the events |

Keep the identifiers. They locate the integration when you investigate a
problem.

A change of the agent name display responds *Preference updated.* or *Could not update the preference.*. If the
screen does not load, it shows *Could not load the Chatwoot integration.*
and the **Try again** button.

### Deactivate without deletion

The integration has a switch with the labels **Integration enabled** and **Integration disabled**. The change confirms
with *Integration status updated successfully.* or fails with *Error updating integration status.*

Deactivation is not deletion. On deactivation:

- The integration stops operating. Conversations stop being mirrored.
- The registration remains, with the same identifiers, URL, token, and inbox name.
- The inbox and the webhook created in Chatwoot continue to exist.
- Activation again resumes the operation, with no reconfiguration.

Use deactivation to pause temporarily.

### Delete

<Warning>
**The deletion cannot be undone.** The deletion removes the inbox and the webhook
created in your Chatwoot. To go back, create the integration again. The new inbox
will have another identifier. To stop temporarily, deactivate instead of
deleting.
</Warning>

Click **Remove Chatwoot integration**. The
dialog *Remove Chatwoot integration?* asks for confirmation. Click **Delete** or **Cancel**. Success: *Chatwoot integration removed.*
Failure: *Could not remove the Chatwoot integration.*
