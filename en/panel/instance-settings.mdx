## Description

The screen **Instance Settings** (`dash/instances/[id]/settings`) controls the behavior of the instance on send
and receive. It has two tabs, **Messages** and **Integration**, and the card **Storage**.

Every change in the tabs applies only after **Save settings**. The
panel confirms with *Settings updated successfully.* The card **Storage** has
its own button. See [Storage card](#storage-card).

The same options exist in the API. See
[Get settings](/api-reference/configurações/obter-configurações) and
[Update settings](/api-reference/configurações/atualizar-configurações).

## Messages tab

### Delay between messages

The interval the instance waits between one send and the next. The field has four
levels:

| Level | Interval |
|---|---|
| **Shortest** | 0.5 to 2 seconds |
| **Short** | 2 to 3 seconds |
| **Medium** | 5 to 7 seconds |
| **Long** | 10 to 12 seconds |

At the shortest level, the queue moves faster. At the longer levels, the send
looks more like the rhythm of a person, and a large queue takes longer to drain.
See [Message queue](/en/definitions/queue).

### Send presence update

Sends the recipient the status *typing...* or *recording audio...* before the
message.

- **On**: the recipient sees the status before the message arrives.
- **Off**: the message appears without the status.

<Note>
This feature adds a delay of 5 to 15 seconds to each message. The delay adds to
the delay between messages.
</Note>

### Enable link preview

Shows a preview of the first link of the message, based on the link metadata.

- **On**: the first link arrives with a title and a preview image.
- **Off**: the link goes as text.

It applies only to the first link of each message.

### Mark messages as read

Marks received messages as read automatically.

- **On**: the sender sees the blue double check mark as soon as the instance receives the message.
- **Off**: the message stays unread for the sender, even after your system processes it.

## Integration tab

These options apply to the behavior with AI agents. See
[Integrations](/en/panel/integrations).

### Debounce

The wait time, in seconds, before the instance sends the user messages to the AI
agent.

| Field | Required | Validation |
|---|---|---|
| **Debounce** | Yes | Greater than 0 and less than 20 seconds |

Outside the range, the panel responds *Debounce must be greater than 0* or *Debounce must be less than 20*.

When the contact sends three messages in a row, the debounce makes the instance
wait and send the three to the agent at once, as a single context. A low value
replies faster and increases the chance of a reply before the person finishes. A
high value groups better and takes longer to reply.

### Split agent messages

Splits the agent reply into smaller parts, at the blank lines of the text.

- **On**: a long reply arrives as several messages.
- **Off**: the reply arrives as one message.

### Process image links

Converts the image links of the agent reply into image files.

- **On**: an image link becomes an image in the chat.
- **Off**: the link arrives as text.

### Reply with audio

Replies with audio to messages received as audio.

- **On**: a contact who sends audio receives audio. A contact who sends text receives text.
- **Off**: the reply is always text.

### Default ElevenLabs voice

The voice used in audio replies when the send does not specify another voice.

<Note>
The voice list depends on the ElevenLabs key registered on the instance. Without
the key, there are no voices to choose. Register the key in
[Text to speech](/en/panel/text-to-speech).
</Note>

### Disable AI on messages from the device

Disables the AI in a conversation when the line owner sends a message from the
phone, from WhatsApp Web, or from Desktop.

- **On**: when a human agent replies from the phone or from WhatsApp Web, the
  agent stops replying in that conversation. The two do not talk to the customer
  at the same time.
- **Off**: the agent continues to reply after the human intervention.

## Storage card

The card **Storage** registers the own storage of the instance. With the
registration, ZapperHub stores the received media, the sent media, and the call
recordings in a storage of yours, compatible with the S3 API. Without the
registration, the files stay in the ZapperHub storage for 7 days. See
[Own storage](/en/definitions/storage#own-storage).

The badge adjacent to the title gives the state:

| Badge | Meaning |
|---|---|
| **Not configured** | The instance does not have an own storage |
| **Active** | ZapperHub stores the files in your storage |
| **Failing** | The last write to your storage failed. The card shows the date and the cause |

### Preliminary requirements

- A bucket with an access key that can write and delete objects.
- A public `https` address for the storage API.
- For the event URL to open in a browser: public read on the bucket, or a public
  read domain, such as a CDN.

### Fields

| Field | Required | Validation |
|---|---|---|
| **API endpoint** | Yes | URL that starts with `https://`. Error: **Enter a URL that starts with https://** |
| **Bucket** | Yes | Text. Error if empty: **Required field** |
| **Region** | Yes | Text. On Cloudflare R2, use `auto` |
| **Prefix (optional)** | No | Folder of the files. Error: **The prefix cannot start with /** |
| **Public URL (optional)** | No | URL that starts with `https://`. It is the base of the event URLs |
| **Access Key ID** | Yes | Text |
| **Secret Access Key** | Yes | Text |
| **Use the bucket in the URL path** | No | Turn on if the provider requires the format `endpoint/bucket/file` |

Without the **Public URL**, the event URL uses the API endpoint and the bucket.

### Register or change the storage

<Steps>
  <Step title="Fill in the fields">
    Enter the endpoint, the bucket, the region, and the access key.
  </Step>
  <Step title="Save">
    Click **Save storage**. The button shows **Testing the storage...** while
    ZapperHub writes and deletes a test file.
  </Step>
  <Step title="Examine the state">
    The panel confirms with **Storage saved. The write test passed.** The badge
    changes to **Active**.
  </Step>
</Steps>

<Note>
The panel does not show the saved credentials. To change the registration, enter
the **Access Key ID** and the **Secret Access Key** again.
</Note>

If the test fails, the panel does not save the registration and shows the cause:

| Message | Cause |
|---|---|
| **Could not write the test file to your storage** | The credentials, the bucket, or the write permission are incorrect |
| **The test file was written, but it could not be deleted** | The access key does not have the delete permission |
| **The storage endpoint must use https and point to a public address.** | The address does not use `https` or is not public |

The first two messages include the code that your storage returns.

### Remove the storage

<Steps>
  <Step title="Start">
    Click **Remove**. The panel opens **Remove your own storage?**
  </Step>
  <Step title="Confirm">
    Click **Remove**. **Cancel** closes without removal.
  </Step>
</Steps>

The panel confirms with **Storage removed.** The new files go to the ZapperHub
storage again. ZapperHub does not delete anything in your storage.

### Through the API

The same operations exist in the API: `PUT`, `GET`, and `DELETE` on
`/{instanceId}/storage`. See [Own storage](/en/definitions/storage#own-storage).
