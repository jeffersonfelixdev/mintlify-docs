## Description

The screen **Configure your Global API Key** (`dash/api-key`) manages the key of the account. It is different from the key of
each instance. Confusion between the two is the most common cause of a `401`
error.

## Which key to use

| | **Global key** | **Instance key** |
|---|---|---|
| **Name in the panel** | Global API Key | X-Api-Key |
| **Location** | Side menu > Global API Key | In the instance row, in [Instances](/en/panel/instances) |
| **Scope** | The whole account | One instance |
| **API** | Instance API | Instance API routes (messages, chats, settings) |
| **Header** | `Authorization: Bearer <key>` | `x-api-key: <key>` |
| **Function** | Create, rename, list, and delete instances | Send messages and operate the instance |
| **Reference** | **Instance API Reference** tab. Example: [Get all instances](/api-reference/instâncias/obtém-todas-as-instâncias) | **API Reference** tab. Example: [Get settings](/api-reference/configurações/obter-configurações) |

Rule: if the call creates or manages instances, use the global key. If the call
operates inside an instance (send a message, read a chat, configure a webhook),
use the instance key.

The concept of the two keys is in [Authentication](/en/definitions/authentication).

## Create the key

With no key, the screen shows *No global key has been created* and the button **Create global key**.

<Steps>
  <Step title="Create">
    Click **Create global key**. The panel opens the dialog *New Global Key Created*.
  </Step>
  <Step title="Copy the key">
    Click the copy button. The panel confirms with *Key copied to clipboard!*.
  </Step>
  <Step title="Store the key">
    Save the key where your application will read it. Then click **Got it, close**.
  </Step>
</Steps>

If the creation fails, the panel shows *An error occurred while creating the global key*.

<Warning>
**The key is shown once.** After you close the dialog, neither you nor support
can see the key again. Copy the key before you close the dialog. If you lose the
key, use **Rotate** to generate another one.

Do not put the key in versioned code, in a support message, or in any public
place.
</Warning>

## Rotate

The **Rotate** button replaces the current key with a new one. Use
the rotation when you lost the key or suspect a leak.

<Warning>
**The rotation invalidates the previous key immediately.** Every application that
still uses the old key receives an authentication error immediately. There is no
overlap period between the two keys.

To rotate without a service interruption: have access to the applications ready
before you confirm. Rotate, copy the new key, and update the applications right
after. The downtime lasts from the rotation to the update.
</Warning>

<Steps>
  <Step title="Start the rotation">
    Click **Rotate**. The panel opens *Confirm key rotation*.
  </Step>
  <Step title="Confirm">
    Click **Yes, rotate key**.
  </Step>
  <Step title="Copy the new key">
    The new key appears in the dialog *New Global Key Created*. Copy and store the key. It is also shown once.
  </Step>
  <Step title="Update the applications">
    Replace the key in all applications that use the Instance API.
  </Step>
</Steps>

## Delete

The **Delete global key** button opens the dialog
*Confirm deletion*.

<Warning>
**The deletion cannot be undone.** The account is left with no global key. Every
call to the Instance API fails until you create another key. Existing instances
are not deleted and continue to operate with their own keys. Only the management
through the Instance API stops.

To replace the key, use **Rotate**, which creates the replacement in the same
step.
</Warning>

Click **Yes, delete**. Success: *Global key deleted successfully*. Failure: *An error occurred while deleting the global key*.
