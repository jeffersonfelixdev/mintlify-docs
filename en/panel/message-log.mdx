## Description

This screen lists the messages sent and received by the instance. For each
message, it shows what happened and when. Use the screen to investigate a message
that did not arrive.

With no result for the filters, the screen shows *No messages found*. If the query fails: *Could not load messages*.

## Filters

| Filter | Function |
|---|---|
| **Creation date** | Period between **From** and **To** |
| **Sent/Received** | **All**, **Sent only**, or **Received only** |
| **Origin** | Where the message came from. The panel summarizes it as *(direction) via (origin)* |
| **Search** | Text search in the content and the caption |

With inverted dates, the screen warns: *Start date cannot be after end date*.

The list loads in blocks. Click **Load more**.

### Columns

**Contact**, **Type**, **Text / caption**, **Created at**, and **Status**. The
direction appears as **Sent** or **Received**.

## Message types

Text, Image, Audio, Video, Document, Sticker, Location, Contact, Button, List,
Carousel, and Unknown.

The **Unknown** type appears when the message does not fit any
of the categories. Usually, it is a new WhatsApp format.

## Receipt states

Click a row to open **Message details**. The four states
appear there, each one with the date and time:

| State | Meaning | Timestamp |
|---|---|---|
| **Sent** | ZapperHub delivered the message to WhatsApp | **Sent at** |
| **Delivered** | WhatsApp delivered the message to the recipient device | **Delivered at** |
| **Read** | The recipient opened the chat and saw the message | **Read at** |
| **Send error** | The message did not complete the path | No timestamp. See **Error code** and **Error message** |

The states are cumulative, in this order. How to interpret:

- **Sent at** filled and **Delivered at** empty: the message left ZapperHub, but
  WhatsApp has not delivered it yet. The device can be offline, or the number can
  be invalid.
- **Delivered at** filled and **Read at** empty: the message reached the device
  and was not opened yet. This is normal behavior.
- **Send error**: the failure is in **Error message**, with the **Error code**.

The details also show **ID**, **Instance ID**, **Message type**, **Origin**,
**Phone (PN)**, **LID**, **Name**, **Content**, **URL**, **Caption**, **MIME
type**, **File name**, **Created at**, **Answered at** and, when the message
quotes another, **Quoted message ID** and **Quoted message content**. On
templates: **Template name** and **Template type**. On Instagram: **Instagram ID**.

### Quick reply

The details have the **Quick reply** field and the **Send** button. The result is *Message sent successfully* or
*Could not send the message*.

## Delivery receipts in webhooks

A message delivered to the recipient and an event delivered to your system are
different things. The shortcut **View delivery receipts** opens **Webhook delivery receipts**, which shows the second one:

| Field | Content |
|---|---|
| **ID** | The identifier of the receipt |
| **Delivered at** | When the event reached your endpoint |
| **Delivery attempt made at** | When the delivery was attempted |
| **Error** | The error message, when the attempt failed |

With no results: *No delivery receipts found*. On
failure: *Could not load receipts*.

How to use: if the message shows as **Delivered**, but your system did not react,
the problem is in the webhook delivery, not in WhatsApp. Compare **Delivery
attempt at** with **Delivered at**. An attempt with no delivery, with **Error**
filled, means that your endpoint refused or did not respond. Review the webhooks
in [Webhooks](/en/panel/webhooks).

## Processing queues

The cards on the instance screen open the **Message report**, at the `dash/instances/[id]/messages/[status]` route. It is the
same list, restricted to one processing state:

| State | Name in the navigation |
|---|---|
| **Active** | **Messages in progress** |
| **Completed** | **Processed messages** |
| **Failed** | **Messages with error** |
| **Waiting** | **Messages in queue** |

The report shows the record count and the columns **TYPE**, **JID**,
**TEXT/CAPTION**, and **DATE/TIME**. If the query
fails: *A request error occurred. Please try again.*.

When you open an item, these appear: **Recipient**, **Contact**, **Group**,
**Message/Caption**, **Created at**, **Processed at**, **Finished at**, **Error**,
and **Attempts made**.

The queue operation is in [Message queue](/en/definitions/queue).
