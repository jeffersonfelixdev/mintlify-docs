## Description

The group routes are available only for instances connected by QR Code. An
instance of a different type receives `422` with the code
`UNSUPPORTED_FOR_INSTANCE_TYPE`.

## Operations

The API supports these operations on groups:

- Create a group.
- List the groups the number participates in.
- Get the details and the participants of a group.
- Change the name and the description of a group.
- Change and remove the photo of a group.
- Add and remove participants.
- Promote a participant to admin and remove that permission.
- Get the invite link.
- Reset the invite link.
- Change the settings of a group.
- List, approve and reject join requests.
- Get the data of an invite without joining the group.
- Join a group with an invite.
- Leave a group.

The routes are in the *Grupos* section of the
[API Reference](/api-reference).

For communities, refer to [Communities](/en/functions/communities).

To send text and media to a group, use the
[Sending messages](/en/functions/sending-messages) routes with the group JID in
`jid`.

## Create a group

Give the name and at least one participant. The connected account is the
creator and the first admin of the group.

The response has two fields:

- `group`: the data of the new group, with the JID in `id`. The
  `participants` list contains only the participants that joined the group.
- `participants`: the result for each requested participant. Refer to
  [Result per participant](#result-per-participant).

WhatsApp creates the group also when it rejects some of the participants.

## Result per participant

WhatsApp accepts or rejects each participant separately. The group creation,
the participants route and the approval of join requests respond with a list
that has one item for each participant:

| Field | Description |
|---|---|
| `id` | JID or LID of the participant. In groups that use LID, the value can be the LID also when the request used the number. |
| `phoneNumber`, `lid` | Number and LID of the participant, when WhatsApp gives them. Use these fields to relate the item to the request. |
| `success` | `true` when the action applied to the participant. |
| `error` | Code (`code`) and reason (`reason`) of the rejection. Only present when `success` is `false`. |
| `invite` | Invite code and expiry (`expiresAt`, in epoch ms). Only present when the reason is `invite_required`. |

The most frequent reasons are:

| `reason` | Code | Meaning |
|---|---|---|
| `invite_required` | 403 | The privacy settings of the participant allow entry only by invite. Send the group invite link to the participant. |
| `invalid_phone_number` | 404 | The number does not have WhatsApp. |
| `temporarily_blocked` | 408 | The participant left the group a short time ago. |
| `conflict` | 409 | To add: the participant is already in the group. |
| `group_full` | 419 | The group has the maximum number of participants. |

A code that is not in this list comes with the reason `unknown`.

<Note>
The participants route responds `200` also when WhatsApp rejects all the
participants. Examine `success` in each item.
</Note>

## Change the name and the description

Send `name`, `description` or the two. When the body has the two fields, the API
changes the name first.

<Warning>
If the change of the description fails, the new name stays saved. Get the group
to see the current state before you send the change again.
</Warning>

## Reset the invite link

<Warning>
When you reset the invite link, the previous link stops working.
</Warning>

The response contains the new link in `inviteLink`.

## Change the settings

Send one or more of these settings:

| Field | Effect |
|---|---|
| `announce` | `true`: only admins send messages. |
| `restrict` | `true`: only admins change the name, the description and the photo. |
| `joinApprovalMode` | `true`: a person who joins with the invite link must get the approval of an admin. |
| `ephemeralDuration` | Disappearing messages, in seconds: `0` (off), `86400` (24 hours), `604800` (7 days) or `7776000` (90 days). |

The API applies the settings in this sequence: `announce`, `restrict`,
`joinApprovalMode`, `ephemeralDuration`.

<Warning>
If a setting fails, the previous settings stay saved. Get the group to see the
current state before you send the change again.
</Warning>

## Join requests

When `joinApprovalMode` is `true`, a person who uses the invite link sends a join
request. To process the requests:

<Steps>
  <Step title="List the requests">
    Send `GET /{instanceId}/groups/{groupId}/requests`. The response contains the
    `id` of each pending request.
  </Step>
  <Step title="Approve or reject">
    Send `PATCH /{instanceId}/groups/{groupId}/requests` with the `id` values in
    `participants` and `approve` or `reject` in `action`.
  </Step>
</Steps>

The response contains the result for each request. Refer to
[Result per participant](#result-per-participant).

## Join a group with an invite

Give the invite link or only the code in `invite`.

To see the data of the group before you join, send
`GET /{instanceId}/groups/invite-info?invite=<link or code>`. This query does
not cause the account to join the group.

To join, send `POST /{instanceId}/groups/join`. The response has two fields:

- `groupId`: the JID of the group.
- `pendingApproval`: `true` when the group requires approval. In that case, the
  account joins the group only after an admin approves the request.

## Leave a group

<Warning>
After it leaves, the account can go back to the group only with an invite or
when an admin adds it.
</Warning>

Send `POST /{instanceId}/groups/{groupId}/leave`.

## Rejection by WhatsApp

Some operations require that the connected account is an admin of the group.
For example: change participants, get the invite link, change the settings,
process join requests and, in groups with restricted editing, change the name,
the description and the photo.

When WhatsApp rejects the operation, the API responds `422` with the code
`PROVIDER_REJECTED`. The reason is in `detail`.

<Note>
If the connected number is not an admin of the group, Meta can hide the phone
numbers of the participants. In that case, the API shows the LID of the contact
instead of the number.
</Note>
